# SceneGo 开源版部署与配置总指南

> 重要：SceneGo 开源版是源代码发行，不是托管服务、安装包、容器镜像或一键部署产品。
> 公开发布方不替使用者安装、编译、打包、部署、配置、升级或运维任何组件。

如需先了解产品流程，可访问官方托管体验版：<https://tv.ostory.ai>。注册时使用中国大陆
手机号完成滑块验证和短信验证，再设置密码；登录后新建项目和分集即可开始体验。托管版
与本仓库的自行部署版本是两种交付形态，功能版本、模型和服务配置可能不同。

本目录定义公开版的发行边界和部署方法。使用者必须理解并独立完成部署过程，至少包括：取得源码、核对版本、安装系统依赖、创建 Python 虚拟环境、安装 Python 依赖、安装 Node.js 依赖、分别编译两个前端、安装和加固 PostgreSQL、安装和加固 Redis、运行数据库迁移、创建运行目录、配置第三方平台 API、配置反向代理与 TLS、建立系统服务、配置日志轮转、备份、监控以及升级回滚。

## 2. 公开版明确不提供什么

公开版不提供：

- Dockerfile、Compose、Podman、Kubernetes、Helm 或任何容器部署文件；
- 预构建前端、可执行文件、安装包、压缩包、容器镜像或制品下载；
- 安装、初始化、部署、启动编排、升级、回滚工具或脚本，无论是否标为“一键”；
- Shell、PowerShell、批处理部署助手，或 Makefile、Justfile、Taskfile 等整合任务入口；
- 已经整合好的 PostgreSQL、Redis、反向代理、TLS、对象存储或系统服务配置；
- 生产环境域名、主机地址、账号、密钥、令牌、证书或内部网络信息；
- 项目内部开发的 ComfyUI Agent、节点、工作流 JSON、模型目录、启动器、GPU 调度器、远程更新器或节点运维脚本；
- 发行方代为申请、充值、保管或轮换任何第三方 API 凭据；
- 安装、配置、运维、二次开发、故障排查或数据恢复承诺。

文档中的命令是部署示例，不是一键部署脚本。使用者必须根据自己的操作系统、目录、用户、网络、域名、数据库策略和安全策略进行调整。

使用者必须在终端分别执行依赖安装、类型检查、测试、编译和应用启动命令。公开仓库保留 `package.json`、依赖锁文件、TypeScript/Vite 编译配置和数据库迁移源文件；这些是保证源码可构建、版本可核验的工程输入，不替使用者安装中间件、创建服务、上传产物或部署整套系统。不会通过删除必要依赖或省略步骤来制造无法完成的安装过程。

## 3. 公开版提供什么

公开版提供：

- 可由使用者自行检查和编译的应用源代码；
- 不含真实凭据的配置字段说明和占位示例；
- 数据库结构及迁移方法；
- 前端与后端的编译、测试和运行说明；
- 第三方在线 API 的配置说明；
- 标准化扩展边界和 ComfyUI 官方接口原理说明；
- 安全加固、备份、升级、回滚和自助排障清单。

“支持本地 ComfyUI”表示公开版说明如何基于 ComfyUI 官方 HTTP/WebSocket 接口自行设计连接器，并保留可扩展边界；不表示公开发布方交付内部自研的本地节点代码或工作流。

## 4. 使用者责任

使用者是自己部署实例的系统管理员和数据控制者，必须自行承担：

- 选择兼容的操作系统、Python、Node.js、PostgreSQL、Redis、FFmpeg 和反向代理版本；
- 阅读每个依赖和第三方平台的许可证、服务条款、地区限制、计费与内容政策；
- 创建最小权限系统用户、数据库用户和 API Key；
- 确保密钥只存在于服务端秘密存储中，绝不进入浏览器包、Git、日志、截图或工单；
- 配置 TLS、防火墙、访问控制、速率限制、日志脱敏、备份、恢复演练和安全更新；
- 在升级前备份数据库和媒体文件，并在隔离环境验证迁移与回滚；
- 对自建 ComfyUI、自定义节点、模型权重和工作流进行来源审计、许可证审计和恶意代码审计；
- 对生成内容、上传素材和个人信息取得必要授权并依法处理。

## 5. 发行与更新要求

首次发行和后续更新都必须满足以下条件：

- 使用全新、经过审查的 Git 历史，不继承包含私有部署或本地节点实现的旧对象；
- 已选择并加入明确的开源许可证，且完成上游版权和第三方许可证核验；
- `python deploy/scripts/check_public_release_boundary.py --candidate-root <公开候选目录>` 通过；
- `python deploy/scripts/check_public_import_boundary.py` 通过，确认公开入口的完整 Python 导入闭包不触达私有本地执行模块；
- 开源卫生、依赖漏洞、密钥历史、前后端测试和生产构建全部通过；
- 不包含本页“明确不提供”的任何文件或实现；
- 发行者已填写真实的私密安全报告渠道和商业支持联系渠道。

SceneGo 的首次发行使用独立、全新的 Git 历史。后续同步必须继续审查新增对象，不能把开发仓库的历史或被公开边界排除的文件合并进来。
