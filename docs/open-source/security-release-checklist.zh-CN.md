# 开源版安全审计与发布门禁

源码公开会显著降低攻击者理解系统内部结构的成本。正确的安全目标不是“隐藏实现”，而是保证即使攻击者能够阅读全部公开源码，也不能绕过鉴权、越权访问数据、伪造回调、窃取密钥或控制执行节点。

本文是发布门禁，不是一次性的形式检查。每个候选提交、每个依赖升级和每个正式发布都要重复执行。静态审计通过不等于渗透测试通过，也不等于生产部署自动安全。

## 1. 当前发布结论的判定方式

只有所有阻断项关闭后，候选版本才能标记为可发布。以下任一项存在时必须判定为 `BLOCKED`：

- 当前或历史 Git 对象含凭据、内部域名、生产配置或禁止公开的本地执行代码；
- 缺少明确的开源许可证、第三方许可清单或版权归属确认；
- 存在已知高危依赖漏洞且没有验证过的缓解措施；
- 管理员权限可以由固定用户名、固定用户 ID 或客户端字段自动获得；
- 私有媒体能够通过静态路径绕过对象级授权；
- Token 被放进 URL、前端持久化存储或可被日志记录的位置；
- API 密钥在加密配置缺失时降级为明文或 Base64；
- 详细健康接口、队列、节点、供应商或版本信息匿名公开；
- 公开候选包包含 Docker、预构建产物或 Ovideo 开发的 ComfyUI 本地实现；
- 安全报告渠道尚未填写有效的私密联系方式。

## 2. 威胁模型

发布前至少覆盖以下攻击者和资产：

| 攻击者 | 可能能力 | 重点保护资产 |
| --- | --- | --- |
| 未登录互联网用户 | 枚举接口、上传恶意文件、消耗资源 | 服务可用性、公开元数据 |
| 普通注册用户 | 调用业务 API、持有自己的 Token | 其他用户项目、媒体、点数和任务 |
| 恶意项目成员 | 接触共享项目内容 | 项目边界、角色权限、审计记录 |
| 泄露 Token 的攻击者 | 重放合法会话 | 账号、生成额度、私有素材 |
| 被攻陷的供应商或 Worker | 返回恶意 URL、路径或媒体 | 内网、对象存储、任务状态 |
| 阅读源码的攻击者 | 精确了解路由、字段和默认值 | 所有部署实例和运维入口 |
| 恶意依赖或 Custom Node | 在服务器执行代码 | 主机、密钥、数据库和 GPU 节点 |

## 3. Git、秘密和发布历史

- 对整个候选历史运行秘密扫描，不只扫描当前工作树；
- 对所有历史命中逐项人工判断，无法证明是假值时立即撤销和轮换；
- 删除当前文件不能清除 Git 对象；优先从全新、经过审核的历史发布；
- 不把生产数据库、媒体、日志、备份、诊断包或 `.env` 放入候选仓库；
- 验证仓库可见性、默认分支、保护规则、Fork 和镜像；
- 从全新克隆执行全部门禁，确保未跟踪文件没有掩盖问题；
- 发布前生成并保存候选提交哈希、来源清单和审计证据。

## 4. 身份认证、会话与管理员权限

- 生产环境缺少 JWT 签名密钥时必须启动失败，不能自动生成临时密钥；
- 使用足够强的随机密钥，分别管理签名、API 配置加密和 Worker 认证；
- Access Token 短时有效，刷新 Token 可撤销并支持轮换；
- 密码修改、找回、账号封禁和角色降级后撤销旧会话；
- 不在 `localStorage`、查询参数、下载 URL、SSE URL 或日志中传递长期 Token；
- 管理员只能通过明确的一次性引导或数据库授权产生；
- 固定用户名、手机号、邮箱或用户 ID 永远不能自动获得管理员权限；
- 登录、注册、验证码、找回密码和敏感操作必须限速；
- CAPTCHA 字段若存在必须真正验证；不使用的字段应删除，避免虚假安全感；
- CAPTCHA 后端必须检查用途 action 与允许 hostname；供应商超时、配置缺失或 Redis 登录限速不可用时生产环境失败关闭；
- 密码登录同时按 HMAC 匿名化后的身份和来源 IP 限速，429 返回可信的 `Retry-After`；
- 审计登录失败、权限变更、密钥修改和管理员操作，但不记录口令或 Token。

## 5. 对象级授权

每个读取或修改项目、分集、分镜、素材、生成结果、分享、账单和回收站对象的接口，都要在服务端检查当前主体是否拥有该对象的权限。

- 不依赖前端隐藏按钮；
- 不只检查“已登录”，还要检查对象归属和项目角色；
- 批量接口逐个验证对象；
- 下载、缩略图、流媒体和静态文件路径也执行相同授权；
- 分享链接使用独立、可撤销、限时的随机能力 Token；
- 数据库查询带入租户/用户/项目约束，不能先查出对象再由前端过滤；
- 404 与 403 的选择要避免泄露对象是否存在。

旧版整项目快照保存（`/api/projects/save` 和 `/api/workspace/save-beacon`）沿用所有者写入规则，不因加入项目获得整份快照覆盖权限；协作成员通过分集、分镜、素材等对象接口按角色操作。保存必须先校验归属再读取旧集合或处理图片；数据库未实际写入时不得返回保存成功，查询故障也不能当作“项目不存在”继续写入。

异步配音提交也必须校验输出项目、分集、分镜和角色声音绑定的成员写入权限，不能因为输入只有文字就跳过对象授权。校验须发生在供应商调用、任务入队和点数冻结之前；同时提供输出范围和角色声音时，两者必须属于同一项目。公开入口的延迟任务服务适配还须保持真实方法签名兼容，不能仅用接受任意参数的替代对象证明调用链有效。

后台项目分组由两个入口共用 `routers/admin_project_groups.py`，前后台使用相同分组 ID、项目归属和计数。管理员可为用户整理分组，但不能把项目放进另一用户的分组，不能借分组操作转移项目所有权；删除分组只解除关联，保留项目和成员权限。验收须覆盖管理员与超级管理员的完整增删改查、未分组项目、移动项目、普通用户及匿名拒绝、失败不写成功审计、审计操作者的稳定用户 ID。

FastAPI 的鉴权依赖使用仅接收 `Request` 的会话适配函数。服务层用于测试注入的身份加载器、会话校验器必须留在服务器内部，不能成为 HTTP 参数；开发模式的 OpenAPI 生成须成功且不包含这些内部参数。生产模式仍禁用文档与 schema 发现接口，不能通过开放生产文档规避这一检查。

点数后台的八个操作由两个入口共用 `routers/admin_credits.py`。管理员可查询与人工调整，规则写入仅限超级管理员；审计操作者使用稳定用户 ID。回归须覆盖非法金额、冻结余额保护、降权、规则上下限并发修改、重复删除审计和充值订单筛选。公开源码树也须保留并执行 `test_public_admin_credits.py`，不能把只注册路由当作功能完成。详见[后台点数管理契约](../architecture/admin-billing-contract.md)。

## 6. 媒体上传、下载和文件处理

- 对请求体、单文件、总文件数、像素、帧数和解压后大小设置上限；
- 同时验证扩展名、MIME、文件头和实际解码结果；
- 上传文件使用服务器生成的对象名，拒绝路径穿越和控制字符；
- 图片、音频、视频解析放入低权限隔离进程，设置 CPU、内存和执行超时；
- 私有媒体不能直接挂载为匿名静态目录；
- 下载响应使用对象级授权或短时签名 URL；
- 缩略图和转码产物继承原始素材权限；
- 删除采用可恢复流程并记录引用关系，避免删除仍被项目使用的素材；
- 对 FFmpeg、图片库、压缩库和媒体探测工具持续更新并做漏洞扫描。

## 7. 外部 API、Webhook、代理与 SSRF

- 供应商 Endpoint 默认从服务器允许列表选择；自定义地址只允许受权管理员使用；
- 解析域名后拒绝回环、链路本地、私网、云元数据和保留地址，防止 SSRF；
- 重定向后再次验证目标；
- TLS 验证必须开启，禁止 `verify=False`；
- Webhook 使用签名、时间戳、重放窗口和幂等键；
- 回调中的任务 ID、金额、模型和状态不能直接信任；
- 代理配置不允许普通用户读取或修改；
- 日志对 Authorization、Cookie、API Key、签名和查询参数脱敏；
- 所有外部请求设置连接、读取、总体超时和响应大小上限。

## 8. 数据库、Redis、对象存储和备份

- 禁止默认口令；配置缺失时启动失败；
- 数据库账号采用最小权限，不使用超级用户运行应用；
- Redis 不对公网开放，启用认证、网络隔离和容量策略；
- 对象存储 Bucket 默认私有，使用最小权限访问密钥；
- 迁移先备份、演练和校验，不在生产自动执行未审核迁移；
- 备份加密、设置保留期、隔离访问并定期恢复演练；
- 日志和备份遵守个人数据最小化与删除策略；
- 多用户数据必须有明确租户边界和唯一索引约束。

## 9. 前端与浏览器安全

- 对任何 HTML 渲染点执行上下文正确的转义或可信消毒；
- 不把服务端秘密放入 `VITE_*` 或构建产物；
- 设置严格 CORS 允许列表，禁止带凭据的通配来源；
- 配置 CSP、HSTS、`X-Content-Type-Options`、`Referrer-Policy` 和适当的 `Permissions-Policy`；
- 防止点击劫持；Cookie 使用 `HttpOnly`、`Secure` 和合适的 `SameSite`；
- 外部链接和新窗口避免 `window.opener` 风险；
- 生产关闭调试信息、Source Map 暴露策略需明确；
- 错误提示不返回堆栈、SQL、绝对路径或供应商密钥。

## 10. 依赖、许可证与供应链

- 锁定 Python 与 Node 依赖版本；
- 对生产依赖运行 SCA，人工处理每个高危和严重漏洞；
- 运行 SAST，区分真实漏洞、可接受风险和误报，并记录证据；
- 生成 SBOM，列出直接和传递依赖、版本、许可证与来源；
- 验证前端资产、字体、模型、示例素材和文档截图的授权；
- 构建只在受控 CI 或用户自己的环境完成；公开版不提供预构建包；
- 构建产物应可复现，并能追溯到公开提交；
- 第三方节点、脚本和安装命令不得未经审计自动执行。

## 11. ComfyUI 与本地执行节点

- 公开版不包含 Ovideo 开发的 ComfyUI Agent、工作流、节点或调度代码；
- 用户自建 ComfyUI 不直接暴露公网；
- 节点和工作流视为可执行代码进行审查；
- Worker 使用独立身份、最小权限、短时凭据和任务允许列表；
- 输入输出路径必须规范化并限制在指定根目录；
- 队列查询有超时、字段和大小上限；
- 任务重复提交、断线恢复和结果回传必须幂等；
- GPU 节点不得访问主应用数据库或无关秘密。

## 12. 自动化门禁

后端全量测试须先按 [安装手册的验收说明](manual-installation.zh-CN.md#16-上线前验收) 准备专用回环 PostgreSQL 测试库，并显式设置 `OSTORY_TEST_DATABASE_URL` 与 `OSTORY_REQUIRE_TEST_DB=true`。不能复用业务库或生产凭据。缺少专用测试库时的跳过项必须单独列出，不得计为完整回归通过。

`deploy/tests/test_public_account_isolation.py` 从公开 FastAPI 入口执行双账号 HTTP 回归：真实密码校验、JWT、用户状态和 DAO 配合隔离 PostgreSQL，检查项目保存、素材角色权限、媒体下载、任务的 Redis/数据库读路径、跨站写入以及旧会话失效。Redis 使用进程内替代存储，不启动 Worker；测试账号已完成手机验证，开发环境显式关闭 CAPTCHA。这些测试不等于真实 Redis、验证码注册、反向代理或浏览器端到端验收，仍须完成下列独立检查。

配音回归由 `test_public_minimax_tts_enqueue.py` 校验真实公开入口的调用签名、队列未就绪、配置缺失和错误状态保留；前述账号隔离测试进一步使用实际任务服务、DAO 和计费实现，验证一次合法入队只冻结一次点数，跨账号或跨项目绑定不会产生任务或冻结。测试不执行供应商生成，也不代替结果落盘、播放或实际费用验收。

视频反推须同时保留估价、创建、列表、详情、取消和重试六个操作，两个运行入口共用 `create_video_reverse_router`，仅注入各自的任务服务。`test_public_video_reverse.py` 使用真实账号、数据库、任务服务和点数账本验证权限、参数持久化、重试抢占、处理失败退款和结果原子保存；媒体解码和视觉供应商响应是替代边界。用例还须在独立公开源码树运行，不能依赖私有任务服务。已提交供应商的任务沿用队列取消保护，不承诺立即取消或退款。详见[视频反推运行契约](../architecture/video-reverse-runtime-contract.md)。

`deploy/tests/test_public_lifespan.py` 通过故障注入检查公开入口的启动回滚与关闭顺序：每项资源取得后立即登记清理，先停止消费者再关闭连接；配置加载、Redis 初始化、部分 Worker 创建或关闭失败都不能遗留其余资源和全局引用。这些单元测试使用替代连接，不证明实际服务可启动。候选版本还须使用隔离的真实 PostgreSQL、Redis 和 HTTP 监听完成启动、登录限速、业务数据保存、全新进程重启及签名密钥轮换验收；确认退出后没有残留应用连接。测试库和密钥不得复用生产配置。

涉及主程序及共享 Worker 的修改，还须验证两种运行模式、部分启动期间的信号归属、Worker 心跳及集群检查任务回收，以及全新进程中的模块导入顺序。测试约束见[运行资源归属说明](../architecture/runtime-resource-ownership.md)。混合模式的隔离测试须禁用所有节点，不得把应用连接释放验证当作 GPU 执行或供应商生成验收。

候选目录至少执行：

后端导入边界回归还须在只包含被检查模块的新目录中，以隔离 Python 进程导入公开入口，避免完整开发目录或 `PYTHONPATH` 掩盖缺失依赖。`test_public_import_boundary.py` 覆盖这一检查，并验证私有路径、父包初始化、包导出、相对动态导入、别名和目录外符号链接的拒绝行为。此测试只证明入口可导入，不启动数据库、Redis、Worker 或 HTTP 服务，不等于完整候选安装、业务流程或浏览器验收。

`test_public_runtime_source_isolation.py` 进一步在独立源码测试树中运行发布规则明确列出的公开回归文件。必须配置专用测试 PostgreSQL；子进程隔离模块路径和应用凭据，缺少测试文件、测试失败或跳过均不能计为通过。在线 Worker 心跳断言与私有 Worker 共用不含具体执行依赖的契约，但分别保留测试入口，公开候选不得携带私有生命周期测试实现。此项使用预安装依赖，并沿用各用例的 Redis/供应商替代实现，仍不代表完整候选安装或模型生成实测。

```bash
cd deploy/new_html
npm run typecheck
cd ../../studio
npm run typecheck
cd ..

python deploy/scripts/check_code_comment_language.py
python deploy/scripts/check_open_source_hygiene.py
python deploy/scripts/check_public_import_boundary.py
python deploy/scripts/check_public_route_authorization.py
python deploy/scripts/check_public_frontend_boundary.py --dist-root deploy/dist --studio-dist-root studio/dist
python deploy/scripts/check_public_release_boundary.py --candidate-root /absolute/path/to/public-candidate
python -m pytest -q deploy/tests
```

前端检查必须在两个 `npm run typecheck` 和 `npm run build:public` 都成功以后执行。注释门禁要求源码注释保持必要、简短且使用英文。公开构建在模块解析阶段拒绝加载私有任务、节点或 ComfyUI 中继模块，并在产物生成阶段扫描禁止的本地协议路径、内部节点值和发行方生产域名。只有“源码里删了几个文件”或“页面上隐藏了按钮”都不构成隔离证明。

此外还要运行：Python 依赖审计、Node 生产依赖审计、静态分析、整个 Git 历史秘密扫描、许可证扫描、SBOM 生成、前后端生产构建和独立渗透测试。

自动化通过之后仍需人工逐项检查：

1. 从新的空目录克隆候选仓库；
2. 确认不存在 Docker、镜像、二进制、压缩包和私有 ComfyUI 实现；
3. 严格按公开手册从源码完成安装；
4. 使用全新的非生产凭据完成最小业务流程；
5. 用两个普通账号交叉测试对象越权；
6. 检查匿名媒体、健康接口、OpenAPI 和管理接口；
7. 检查所有日志和浏览器网络记录是否泄露 Token；
8. 执行备份恢复和密钥轮换；
9. 复核许可证、联系方式和不提供技术支持声明；
10. 由发布负责人签字后再创建公开仓库和标签。

还要把 `PUBLIC_SOURCE_FILES.sha256` 与 `git ls-files` 的首次提交清单逐项比对。清单自身不列入自身哈希，`.git/` 不列入清单；除此之外，候选中的普通文件必须全部出现且只有一次。哈希生成之后不允许继续“顺手改文案”，任何变化都必须重新审核并更新清单。边界检查只证明候选与已审核清单一致，不替代代码审查、密钥扫描、许可证扫描或渗透测试。

## 13. 漏洞报告与支持边界

安全漏洞必须通过 `SECURITY.md` 中发布前填写的私密渠道报告，不能提交公开 Issue。安全报告接收不等于提供安装、部署、配置、升级、故障排查或二次开发支持。

开源发布方不随源码提供任何形式的技术支持或可用性承诺。若需要安装、部署、培训、迁移、定制或安全加固服务，应通过官方商业联系方式另行洽谈；是否承接、范围、费用和服务级别以另行签订的协议为准。
