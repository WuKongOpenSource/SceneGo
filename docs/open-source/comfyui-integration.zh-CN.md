# ComfyUI 本地接入教程与公开版边界

Ovideo 公开源码版允许用户连接自己安装、自己维护的 ComfyUI，但只提供协议说明、配置原则和安全要求。公开版不提供、不开源、也不以压缩包、镜像、下载脚本或示例补丁的形式附带任何 Ovideo 已开发的 ComfyUI Agent、任务中继、工作流、节点脚本或部署代码。

这一区分必须反复确认：

- “支持 ComfyUI”表示 Ovideo 可以按照公开协议与用户自己的 ComfyUI 实例交互；
- “支持 ComfyUI”不表示发行方替用户安装模型、Custom Nodes、工作流或 Python 环境；
- “提供接入原理”不表示提供 Ovideo 私有的本地执行实现；
- 用户必须独立完成安装、模型授权核验、节点依赖、安全隔离、工作流设计、容量规划和故障处理；
- 发行方不提供免费或随开源许可附带的技术支持。需要商业技术服务时，请使用发布前填写的官方联系方式。

## 1. 只使用 ComfyUI 官方资料安装

先阅读并以官方文档为准：

- [ComfyUI 手动安装](https://docs.comfy.org/installation/manual_install)
- [ComfyUI Server 通信概览](https://docs.comfy.org/development/comfyui-server/comms_overview)
- [ComfyUI Server 路由说明](https://docs.comfy.org/development/comfyui-server/comms_routes)

官方文档、依赖版本、显卡要求和接口行为可能变化。不要把本文中的示意值当作永久兼容承诺。安装完成后，用户应先在 ComfyUI 自己的界面中独立跑通工作流，再考虑与 Ovideo 对接。

最低自检项目：

1. Python、PyTorch、CUDA 或对应硬件后端版本互相兼容；
2. ComfyUI 能正常启动，且浏览器界面可在受信网络内访问；
3. 所需模型已由用户合法取得，并放在正确的模型目录；
4. 所需 Custom Nodes 已单独安装、锁定版本并完成安全审查；
5. 单独执行工作流时能够产生预期文件；
6. 输出目录有容量上限、清理策略和备份排除规则；
7. ComfyUI 未直接暴露在公网。

## 2. 官方接口的基本工作方式

典型的外部客户端会围绕以下官方接口工作。实际字段必须以当前 ComfyUI 官方文档和实例返回值为准：

| 接口 | 用途 | 对接时必须检查 |
| --- | --- | --- |
| `POST /prompt` | 提交工作流图 | 工作流结构、节点类型、输入大小、返回的任务标识 |
| `GET /ws` | 接收执行进度和状态 | 客户端标识、断线重连、超时、消息大小、终态判定 |
| `GET /history/{prompt_id}` | 查询任务历史 | 任务归属、终态、错误、输出元数据 |
| `GET /view` | 获取输出文件 | 文件名、目录类型、路径穿越、MIME、大小和访问授权 |
| `POST /upload/image` | 上传输入图片 | 文件类型、像素、大小、文件名、存储隔离和恶意内容 |
| `GET /object_info` | 查询节点与输入定义 | 节点允许列表、版本兼容、不要信任任意第三方节点 |
| `GET /queue` | 查看队列 | 只读取必要字段；设置超时和响应大小上限 |

推荐的抽象流程：

1. Ovideo 只把经过校验的媒体和参数交给用户自行实现的适配层；
2. 适配层把业务参数映射成用户自己的 ComfyUI 工作流输入；
3. 适配层调用 `/prompt`，保存 ComfyUI 返回的任务标识；
4. 通过 `/ws` 或有界轮询跟踪状态；
5. 任务结束后调用 `/history/{prompt_id}` 获取输出描述；
6. 对文件名、子目录、MIME、像素和字节数再次验证后，才读取 `/view`；
7. 把文件复制到 Ovideo 自己受控的对象存储，记录来源、哈希和任务关系；
8. 失败、取消、超时和重试必须形成明确终态，不能无限重试或重复扣费。

这只是协议层次的说明。工作流 JSON、节点映射、调度器、Agent、Worker、回调服务、队列中继和部署脚本均由用户自行设计与实现。

## 3. 用户需要自行准备的配置

公开版可以定义通用配置槽位，但不提供可直接工作的 Ovideo 本地执行代码。用户实现适配层时，至少需要自己决定：

| 配置 | 含义 | 安全要求 |
| --- | --- | --- |
| ComfyUI Base URL | 用户实例的服务地址 | 推荐回环地址或私网地址；禁止直接公网暴露 |
| Client ID | WebSocket 和任务关联标识 | 每个调用方独立生成，不放入公开 URL |
| Connect timeout | 建立连接超时 | 应较短，防止连接占满 |
| Read timeout | 单次读取超时 | 与模型耗时分开设置，不能无限等待 |
| Job timeout | 整个任务最长时间 | 超时后进入明确终态并允许人工核查 |
| Max upload bytes | 单文件上限 | 上传前后都检查，防止内存和磁盘耗尽 |
| Allowed MIME types | 允许的媒体类型 | 不只相信扩展名，要检查实际内容 |
| Allowed nodes | 可执行节点白名单 | 拒绝用户未审核的任意节点类型 |
| Output allowlist | 可读取输出目录 | 路径规范化后必须仍在允许根目录内 |
| Concurrency | 最大并发 | 根据显存、内存和节点稳定性设置 |
| Queue limit | 最大排队量 | 超出后快速失败并给出清晰提示 |
| Retry policy | 重试次数与退避 | 只重试可恢复错误；防止重复任务和重复费用 |
| Authentication gateway | 访问控制层 | ComfyUI 本身不足时由用户自行设置可信网关 |

所有配置都应从环境变量或外部秘密管理器读取。不得把口令、网关 Token 或私网凭据写入前端、工作流 JSON、仓库、日志或 URL 查询参数。

## 4. 网络与访问控制

ComfyUI 常见端口不得直接对互联网开放。建议按以下优先级部署：

1. 同机部署时只监听 `127.0.0.1`；
2. 分机部署时使用受控私网、主机防火墙和明确的源地址允许列表；
3. 跨网络访问时通过用户自建的 TLS、身份认证和访问审计网关；
4. 禁止把任意用户输入直接拼接为目标 URL，防止 SSRF；
5. 禁止关闭 TLS 证书验证；
6. 不信任 ComfyUI 返回的文件路径、节点名或媒体类型；
7. 记录任务标识和结果哈希，但日志不得记录认证信息或完整敏感提示词。

如果必须经过反向代理，用户需要自行设置：请求体上限、连接超时、上游读取超时、WebSocket Upgrade、并发限制、访问日志脱敏和 TLS 证书续期。代理能转发请求，不等于代理自动提供正确的身份认证。

## 5. 工作流和 Custom Nodes 安全

ComfyUI 工作流实际上是可执行图。第三方节点通常包含 Python 代码，因此不能把工作流或节点包当成普通静态素材。

用户必须自行完成：

- 逐个核查 Custom Node 的源码、许可证、维护状态和依赖；
- 锁定 Git 提交或发行版本，禁止生产环境自动拉取最新版；
- 使用独立系统账号运行，限制文件、网络和设备权限；
- 禁止节点读取 Ovideo 后端秘密、主机 SSH Key 或其他项目数据；
- 对模型文件和节点包记录哈希；
- 在隔离环境验证更新，再进入生产；
- 为恶意图片、超大图片、解压炸弹和路径穿越设置防护；
- 不执行来源不明的工作流或节点安装命令。

## 6. 任务状态与幂等

用户自建适配层必须保存三类标识：Ovideo 业务任务 ID、适配层请求 ID、ComfyUI `prompt_id`。同一次业务请求重试时必须先查询已有映射，不能无条件再次提交。

建议状态至少包含：`pending`、`queued`、`running`、`succeeded`、`failed`、`cancelled`、`timed_out`。其中：

- 成功必须以历史记录中存在完整输出为准；
- WebSocket 断线不代表任务失败；
- HTTP 提交超时不代表任务没有进入队列；
- 下载失败不代表生成失败；
- 重试下载不应重新生成；
- 取消请求必须说明是“已请求取消”还是“已确认取消”。

## 7. 上线前验收

至少验证以下场景：

- 正常图像和视频任务；
- 不支持的节点、缺少模型、显存不足；
- 上传超限、错误 MIME、损坏文件；
- 队列已满、连接超时、任务超时；
- WebSocket 中断后恢复；
- 同一请求重复提交；
- 输出文件不存在、路径异常、文件过大；
- 服务重启后任务状态恢复；
- 未授权来源访问被拒绝；
- 日志中不存在密钥、Token、Cookie 和完整私密数据。

## 8. 明确不在公开版中的内容

公开候选包若出现以下任意内容，应由发布检查直接阻止：

- Ovideo 开发的 ComfyUI Agent、Worker 或任务中继；
- Ovideo 开发的工作流 JSON、节点映射或默认工作流集合；
- Ovideo 开发的 GPU 节点注册、心跳、调度、输出回传代码；
- Ovideo 开发的 ComfyUI 部署、启动、安装或更新脚本；
- 上述代码改名、压缩、编译或嵌入后的副本；
- 能从公开代码直接还原上述实现的生成物。

如果公开发布确实需要一个接口，应该只保留与具体实现无关、不能直接执行任务的抽象契约，并要求用户从零完成自己的实现。发布审核必须逐文件核对，而不能只看目录名。

## 9. 公开扩展契约如何使用

公开源码中的 `deploy/new_html/public-source/localRuntimeAdapter.ts` 是唯一允许交给本地处理扩展的前端契约。它只做三件事：定义抽象操作名、接收一个由使用者编写的适配器、把已有界面调用转交给该适配器。该文件没有也不得增加网络请求、ComfyUI 地址、端口、工作流、节点映射、模型映射、任务轮询、文件读取或 GPU 调度逻辑。

使用者需要在自己的代码中完成以下工作，而不是等待发行方提供现成文件：

1. 在自己的后端创建经过身份认证和对象授权的本地处理网关；
2. 网关将 Ovideo 的抽象操作映射到使用者自己设计并审计过的工作流；
3. 网关负责上传限制、队列、幂等、超时、取消、状态持久化和结果归档；
4. 使用者在自己的前端源文件中实现 `PublicLocalRuntimeAdapter`；
5. 在 React 应用启动前调用 `registerPublicLocalRuntimeAdapter`，且每次页面运行只注册一次；
6. 重新执行公开前端编译、边界检查和完整验收。

`PublicLocalRuntimeInvocation` 只含 `operation` 和 `args`。`operation` 是稳定的抽象动作，例如 `media.upload`、`material.process` 或 `task.wait`；`args` 保留现有界面的调用参数。使用者必须逐项验证参数，不得把它们直接拼入 URL、文件路径、命令行或工作流 JSON。

适配器不得从浏览器直接连接 ComfyUI。浏览器中不能存放 ComfyUI 网关口令、节点凭据或内部地址。正确边界是“浏览器 → 使用者自己的 Ovideo 后端网关 → 受信网络中的 ComfyUI”。后端网关必须再次验证当前用户、项目、素材和任务归属，不能相信前端传来的所有者 ID。

默认情况下没有注册适配器，所有本地处理入口都会明确报错，公开能力接口也继续返回 `comfyui_available=false`。只有使用者完成自己的后端和前端实现、安全审计并主动修改能力声明后，才可以显示为可用。不要仅修改布尔值或删除报错；那会制造“界面可选但没有安全执行链”的假能力。

发行检查器会阻止在这个抽象契约文件中加入 `fetch`、WebSocket、ComfyUI 官方路由、固定 URL 等实际实现。使用者自己的实现不属于 Ovideo 发行内容，也不得在向上游提交问题时附带其中的凭据、内部地址、工作流或模型路径。
