# SceneGo 开源版配置参数总表

本文解释公开版服务端配置。所有示例值均为无效占位符。任何真实密钥都不得进入 Git、前端变量、浏览器存储、命令行历史、日志、截图或公开工单。

## 1. 配置优先级

数据库连接参数支持进程环境变量和 `deploy/configs/database.env`。进程环境优先。第三方 API 支持管理后台数据库配置和服务端环境兜底；前端不得直接保存供应商密钥。

生产建议使用操作系统秘密管理器或云 Secret Manager，把非秘密配置与秘密配置分开。修改配置后按字段说明决定是否重启；不确定时应先在测试环境重启并验证。

### 参数说明模板

每个参数从六个角度理解：

- **用途**：代码为什么需要它；
- **必填条件**：任何生产实例必填，还是启用某功能才必填；
- **格式**：字符串、整数、布尔、URL 或列表；
- **安全**：泄露、误配或默认值的影响；
- **验证**：如何确认生效而不泄露值；
- **生效方式**：热加载、服务重启或重新编译。

## 2. 运行环境与站点

### `OSTORY_RUNTIME_ENV`

- 用途：区分 `development`、`test`、`production`，控制验证码、绑定令牌和供应商配置的安全行为。
- 必填条件：生产必填，必须是 `production`。
- 格式：小写字符串。
- 安全：缺失时某些模块可能采用开发行为。公开正式版必须在生产缺失时拒绝启动，而不是猜测环境。
- 示例：`OSTORY_RUNTIME_ENV=production`。
- 验证：启动日志只能显示环境名，不能显示秘密。
- 生效：重启后端。

### `CORS_ALLOW_ORIGINS`

- 用途：允许浏览器跨域携带凭据访问后端。
- 必填条件：只有浏览器前端与 API 不同 Origin 时必填；同源部署可以留空。生产环境没有内置发行方域名，留空表示不允许任何跨域来源。
- 格式：以英文逗号分隔的完整 Origin，例如 `https://app.example.invalid`；不要带路径。
- 安全：禁止 `*`，禁止不受控子域，生产不应包含 `http://localhost`。不要为了“先跑起来”加入并不拥有的域名；同源请求无需加入此列表。
- 验证：从允许和不允许的 Origin 分别发送预检请求；不允许来源不能收到许可头。
- 生效：重启后端。

### `TRUSTED_HOSTS`

- 用途：校验请求的 HTTP `Host`，阻止伪造 Host 影响绝对链接、缓存和代理行为。
- 必填条件：生产必填；程序不提供发行方域名或通配符默认值，缺失时直接拒绝启动。
- 格式：英文逗号分隔的纯主机名，可包含经过审查的端口；不要写协议、路径或 `*`。示例：`app.example.invalid,api.example.invalid`。
- 安全：它和 `CORS_ALLOW_ORIGINS` 解决不同问题，不能互相替代。前者检查 Host，后者控制浏览器跨域；两个列表都要独立收紧。
- 验证：使用正确 Host 应正常响应；伪造 Host 应得到 400。反向代理必须保留经过验证的原始 Host，不能传入任意客户端头。
- 生效：重启后端。

### `MAX_REQUEST_BODY_BYTES`

- 用途：限制所有 `POST`、`PUT`、`PATCH`、`DELETE` 请求的总正文大小，早于路由和 multipart 解析生效。
- 默认：104857600 字节（100 MiB）；必须按最大合法请求、并发和内存/临时盘预算重新评估。
- 格式：正整数，单位字节；零、负数和非整数会使服务拒绝启动。
- 安全：这是整次请求上限，不是单文件上限，也不是用户存储配额。反向代理、应用总正文、单文件、解码像素和账户配额必须分别限制。
- 验证：分别测试带正确 `Content-Length`、超大 `Content-Length`、无长度分块上传和边界值；超限必须返回 413，且不进入业务处理。
- 生效：重启后端；反向代理限制需单独重载。

### `ADMIN_PASSWORD`

- 用途：可选内置引导账号的首次登录密码。
- 必填条件：只在首次创建数据库管理员角色时临时设置。
- 格式：至少 8 个字符；生产使用高熵随机值。
- 安全：设置密码本身不会授予管理员角色，还必须完成下面的一次性角色引导。首次成功后立即删除。
- 验证：删除变量并重启后，环境密码不能再次登录；已有账号只能使用数据库认证流程。
- 生效：重启后端。

### `OSTORY_BUILTIN_ADMIN_USERNAME`

- 用途：指定可选内置引导账号用户名，与 `ADMIN_PASSWORD` 配对。
- 默认：未设置时为了开发兼容使用 `admin`；公开生产部署必须显式设置自己的非默认名称。
- 安全：用户名不是授权依据。即使用户名叫 `admin`，数据库角色是 `user` 时也不得进入后台。
- 验证：首次登录后确认 `users.role` 已由一次性引导持久化，再删除引导变量。
- 生效：启动时读取。

### `ALLOW_DEV_ADMIN_PASSWORD`

- 用途：开发模式允许测试管理员密码。
- 必填条件：生产绝对不能启用。
- 格式：布尔。
- 安全：生产设置为 `true` 属于发布阻断。
- 生效：重启后端。

### `ALLOW_PUBLIC_REGISTRATION`

- 用途：控制旧用户名注册兼容接口。
- 必填条件：按产品政策决定；生产建议关闭旧接口，只使用受验证的新注册流程。
- 格式：布尔。
- 安全：默认保持关闭。开启后接口会强制使用与登录相同的 Redis 速率限制，并要求 `register` 动作的人机验证；Redis 或验证码服务不可用时注册失败关闭。部署者仍必须验证用户名保留字、账号枚举风险和管理员初始化隔离，不能因为界面隐藏旧入口就认为接口不存在。
- 验证：未携带有效验证码、连续超限、Redis 中断三种情况都应被拒绝；成功后确认日志没有密码、验证码或完整请求体。
- 生效：重启后端。

浏览器建立会话的登录、手机号注册、手机号登录、旧账号绑定和密码重置请求必须携带精确同源的 `Origin` 或 `Referer`，否则后端拒绝请求，防止跨站页面把访问者静默登录到攻击者账号。命令行或原生客户端没有浏览器 Origin 时，必须显式发送 `X-Ostory-Session-Mode: bearer`，并自行安全保存返回的 Bearer 凭据；该兼容模式不是让网页脚本把 Token 放入 `localStorage` 的开关。

公开入口不注册“批量导出全部明文 API Key”的浏览器接口。供应商配置的备份应通过部署者自己的加密数据库备份、`API_CONFIG_ENC_KEY` 分离保管和受控恢复演练完成。数据库备份与加密密钥不能存放在同一目录、同一下载包或同一管理员浏览器会话中；只有数据库而没有正确加密密钥时，配置应保持不可解密，而不是降级为明文。

## 3. PostgreSQL

### `DB_HOST`

- 用途：数据库主机。
- 必填条件：生产必填。
- 格式：主机名或 IP，不含协议和端口。
- 安全：优先回环或私网；不得指向未验证的公网数据库。
- 示例：`127.0.0.1`。
- 验证：用应用服务账号测试连接，不用管理员账号。
- 生效：重启后端和迁移进程。

### `DB_PORT`

- 用途：PostgreSQL 端口。
- 格式：1 到 65535 的整数，常见为 5432。
- 安全：端口变化不代替防火墙和认证。
- 生效：重启。

### `DB_NAME`

- 用途：Ovideo 独占数据库名。
- 必填条件：生产必填。
- 格式：PostgreSQL 标识符；建议小写字母、数字和下划线。
- 安全：不要与其他应用共用数据库或 schema 所有权。
- 生效：重启；切换前必须执行并核验迁移。

### `DB_USER`

- 用途：应用数据库角色。
- 必填条件：生产必填。
- 安全：不得是 PostgreSQL 超级用户，不应有创建角色/数据库/复制权限。
- 生效：重启。

### `DB_PASSWORD`

- 用途：数据库口令。
- 必填条件：生产必填且不得为空。
- 安全：随机生成、只放秘密存储；轮换时验证新旧连接池切换。
- 验证：只检查“已设置”和连接成功，不打印值。
- 生效：数据库更新口令后同步重启应用。

### `DB_SSLMODE`

- 用途：控制 PostgreSQL 连接传输保护；可用值为 `disable`、`allow`、`prefer`、`require`、`verify-ca`、`verify-full`。
- 默认：未填写时，显式回环主机采用 `disable`，其他主机采用 `verify-full`。
- 生产约束：远程数据库默认只接受 `verify-full`，同时验证加密、证书链和目标主机名。`require` 只表示加密，不能证明连接的是正确服务器。
- 示例：同机回环 `DB_SSLMODE=disable`；远程生产 `DB_SSLMODE=verify-full`。
- 验证：用错误 CA、错误主机名和断开的证书链分别测试，远程生产都必须失败。不要通过关闭证书校验绕过错误。
- 生效：重启所有后端、迁移和 Worker 进程。

### `ALLOW_PASSWORDLESS_LOCAL_DATABASE`

- 用途：在生产模式下，允许经过人工审查的本机 PostgreSQL 使用操作系统/证书等无口令认证。
- 默认：`false`；生产没有 `DB_PASSWORD` 时拒绝启动。
- 风险：该开关不会替你配置 `pg_hba.conf`，也不会证明本地认证安全。只有数据库明确限制到本机、服务账号隔离且认证规则已记录时才可设为 `true`。
- 禁止：不得用它允许远程空口令数据库，也不得为解决连接错误临时开启。
- 生效：重启所有数据库客户端进程。

### `ALLOW_INSECURE_DATABASE_TRANSPORT`

- 用途：对远程生产数据库绕过 `verify-full` 的紧急兼容开关。
- 默认：`false`。
- 风险：这是安全例外，不是普通配置。启用前必须记录网络隔离、证书缺失原因、责任人、到期时间和恢复计划；公开互联网数据库不得启用。
- 验证：安全评审记录和自动配置检查同时存在；问题修复后改回 `false` 并验证 `verify-full`。
- 生效：重启所有数据库客户端进程。

### `DB_POOL_MIN_SIZE` / `DB_POOL_MAX_SIZE`

- 用途：asyncpg 连接池下限和上限。
- 格式：正整数，且最小值不得大于最大值。
- 安全/容量：总连接数约等于每个后端进程的池上限之和，必须小于 PostgreSQL 可用连接数并保留管理连接。
- 示例：小型单进程可从 `2` / `20` 开始压测，不是统一推荐值。
- 生效：重启。

### `DB_MAX_QUERIES`

- 用途：一个连接执行多少次查询后重建。
- 格式：正整数。
- 风险：过小造成连接抖动，过大可能长期保留异常连接状态。
- 生效：重启。

### `DB_MAX_IDLE_TIME`

- 用途：空闲连接最长保留秒数。
- 格式：正整数或代码允许的非负数。
- 风险：结合数据库空闲连接策略设置。
- 生效：重启。

## 4. Redis

### `REDIS_HOST`

- 用途：任务队列 Redis 主机。
- 必填条件：生产必填。
- 格式：主机名或 IP。
- 安全：只用回环或私网，不得公网直连。
- 生效：重启后端/Worker。

### `REDIS_PORT`

- 用途：Redis 端口，常见 6379。
- 格式：整数。
- 安全：改端口不能替代 ACL、防火墙和 TLS。
- 生效：重启。

### `REDIS_DB`

- 用途：逻辑数据库编号。
- 格式：Redis 配置允许的非负整数。
- 风险：逻辑库不是安全隔离；多租户或多环境建议用独立实例/ACL。
- 生效：重启；切换会使旧队列看似消失。

### `REDIS_PASSWORD`

- 用途：Redis 认证口令。
- 必填条件：生产必填，除非使用另行实现的强认证方式。
- 安全：随机、最小权限、不得写进命令参数或日志。
- 生效：Redis 与应用协调切换后重启。

### `REDIS_USERNAME`

- 用途：指定 Redis ACL 用户名；空值表示使用 Redis 默认用户。
- 必填条件：启用 ACL 用户时必填，并与该用户的 `REDIS_PASSWORD` 配对。
- 安全：只授予 Ovideo 所需键前缀和命令。不要使用管理用户，不要给危险管理命令权限。
- 验证：应用用户能执行队列需要的命令，但不能执行配置、清库或访问不相关键空间。
- 生效：先在 Redis 创建/验证新用户，再重启应用，最后撤销旧用户。

### `REDIS_SSL` / `REDIS_SSL_CA_CERTS`

- 用途：启用 Redis TLS，并可指定用于验证服务端证书的 CA 文件。
- 格式：`REDIS_SSL` 为布尔值；`REDIS_SSL_CA_CERTS` 为服务账号可读的 CA 文件路径。
- 默认：TLS 关闭、CA 路径为空。回环开发可接受；远程生产默认拒绝明文连接。
- 安全：远程 Redis 必须使用 TLS 和可信证书。不要关闭证书验证，也不要把私钥、客户端证书或密码放进仓库。
- 验证：正确证书成功，错误 CA/过期证书/主机名不符均失败；同时确认 Redis 端口未对公网开放。
- 生效：重启后端和所有 Worker。

### `ALLOW_UNAUTHENTICATED_REMOTE_REDIS` / `ALLOW_INSECURE_REDIS_TRANSPORT`

- 用途：分别允许远程生产 Redis 无密码、允许远程生产 Redis 明文连接。
- 默认：均为 `false`；任一保护不满足时应用拒绝启动。
- 风险：两者都是需要书面安全评审、责任人、到期时间和补救计划的例外；不能因为服务“在内网”就默认安全。
- 禁止：不得用于公网 Redis，不得写入公开示例的生产值，不得作为排障首选。
- 验证：关闭例外后仍能通过 ACL/TLS 正常连接，才算完成整改。
- 生效：重启后端和所有 Worker。

## 5. 会话、验证码和配置加密

### `JWT_SECRET_KEY`

- 用途：HMAC 会话令牌签名。
- 必填条件：生产必填；程序会拒绝少于 32 字节的值。建议生成至少 64 个随机字节的等效强度，而不是人工编写句子。
- 格式：高熵字符串。
- 安全：绝不能使用示例值、仓库默认值或多个实例各自随机生成的值。泄露后攻击者可伪造身份；轮换会使旧会话失效。
- 启动行为：开发模式可生成本地 `.jwt_secret` 以便首次运行；`OSTORY_RUNTIME_ENV=production` 时不会生成文件或临时密钥，缺失、空值或过短都会直接终止启动。
- 验证：多实例分别签发/验证测试令牌，只比较成功与否，不输出令牌。
- 生效：重启全部后端实例。

### `JWT_ALGORITHM`

- 用途：旧配置层的 JWT 算法标识。
- 格式：当前实现预期 `HS256`。
- 安全：不要允许客户端选择算法；修改必须与实际签名实现和迁移方案一致。
- 生效：重启。

### `JWT_EXPIRE_HOURS`

- 用途：令牌有效期配置。
- 格式：正整数小时。
- 安全：越长，泄露令牌风险窗口越大。应配合会话撤销/版本号和密码重置失效机制。

### 浏览器 Cookie 与显式 Bearer 兼容模式

- 默认登录响应：后端写入 `HttpOnly` 会话 Cookie，JSON 只返回 `session_mode=cookie`，不把 JWT 暴露给浏览器 JavaScript。
- Cookie 属性：生产必须使用 `Secure`、合适的 `SameSite` 和受控 Path；认证响应带 `Cache-Control: no-store`。
- API 客户端兼容：确实需要 Bearer 的非浏览器客户端，可在登录请求加入 `X-Ostory-Session-Mode: bearer`。响应会标记 `session_mode=cookie+bearer` 并返回令牌。
- 安全：不能让普通网页默认请求 Bearer 模式，不能把令牌写入 `localStorage`、URL、日志、分析事件或错误报告。移动端/桌面端需要使用系统安全凭据存储。
- CSRF：Cookie 会自动随请求发送，因此状态修改接口仍需结合 SameSite、Origin/CORS、内容类型和必要的 CSRF 防护审查；`HttpOnly` 只减少脚本读取，不自动解决 CSRF。
- 轮换：密码、账号状态、角色和访问权限变化会递增 `session_version`，使旧 Cookie 与 Bearer 同时失效。

### `users.session_version`（数据库字段，不是环境变量）

- 用途：让无状态签名令牌具备可撤销能力；令牌中的 `sv` 必须与数据库当前值严格相等。
- 初始值：`1`，只允许正整数。
- 自动递增：密码修改或重置、账号禁用、角色变更、模型访问权限变更。
- 不应手工修改：降低数值可能让旧令牌重新有效；批量提高数值会让相关用户全部退出登录。
- 升级行为：没有 `sv` 的旧令牌一律拒绝，升级后用户需要重新登录一次。
- 故障判断：如果数据库字段缺失、类型错误或账号查询失败，鉴权必须失败关闭，不能退回只验签名的兼容模式。
- 生效：影响新令牌；旧令牌按原过期时间处理。

### `OSTORY_VERIFICATION_CODE_SECRET`

- 用途：验证码和绑定凭证相关的服务端秘密。
- 必填条件：生产必填，至少 32 个字符，必须与 JWT 密钥不同。
- 安全：缺失或过短必须拒绝生产启动；仅允许下述滑块验证通过独立 HMAC 域隔离派生摘要，其他用途不得复用。生产推荐独立配置 `OSTORY_CAPTCHA_SECRET`。
- 生效：重启；轮换会使未完成验证流程失效。

### `AUTH_CAPTCHA_REQUIRED`

- 用途：控制公开登录和短信验证码发送前是否必须完成人机验证。当前实现覆盖用户名密码登录、手机号密码登录，以及注册、登录、绑定手机号、找回密码四种短信发送用途。
- 默认：`production` 默认为 `true`，其他环境默认为 `false`。生产环境若主动关闭，相当于把机器人流量全部交给登录限速承担，不符合公开发布基线。
- 格式：布尔值，接受 `1`、`true`、`yes`、`on` 作为真值。
- 安全：使用本站生成的滑块拼图，答案只保存在 Redis。服务端核对后签发随机凭证，登录/短信接口必须原子消费凭证并校验浏览器会话、来源 IP、操作用途，不能只依赖前端回调。
- 失败行为：启用但配置不完整时，生产服务拒绝启动；Redis 不可用时返回 503，不应绕过验证继续登录或发短信。
- 验证：测试缺失、过期、重复凭证、跨会话、跨 IP、错误用途及限速。不得把验证答案、凭证或用户 IP 完整写入日志。
- 生效：重启后端；登录页会在刷新后重新读取公开配置。

### `AUTH_CAPTCHA_PROVIDER`

- 用途：选择人机验证实现。
- 当前值：默认且只接受 `slider`。旧的 `turnstile` 配置必须与代码发布一起切换；启用时其他值会拒绝启动。
- 安全：前后端均在本站完成验证，不加载第三方脚本或 iframe；保留现有密码、短信限速和日预算。滑块不能替代手机号验证，也不能保证抵御专业视觉识别或人工打码。
- 生效：重启后端并刷新登录页。

### `OSTORY_CAPTCHA_SECRET`

- 用途：滑块浏览器绑定和 IP 限速摘要的服务端秘密，各摘要使用独立 HMAC 域。
- 必填条件：生产开启滑块时至少 32 字符，推荐独立高熵随机值。未设置时允许使用现有 `OSTORY_VERIFICATION_CODE_SECRET`。
- 安全：所有实例使用同一值；只保存在后端秘密管理器，不返回浏览器、不记录日志。
- 验证：`GET /api/auth/captcha-config` 只返回 `enabled`、`provider`、`site_key`（后者为 `null`）；设置 HttpOnly、SameSite=Strict 会话 Cookie，生产附加 Secure。
- 生效：重启全部后端实例；轮换后旧挑战和凭证失效，需要重新验证。

### 滑块时效、限速及旧配置迁移

挑战有效期 120 秒，作答容差 5px，每次挑战只能作答一次；成功后的凭证有效期 60 秒且只能消费一次。挑战和作答分别限制每 IP 每分钟 30 次、全站每分钟 600 次；Redis 操作超时 3 秒，浏览器验证请求超时 10 秒，超时不放行。

旧 `TURNSTILE_SITE_KEY`、`TURNSTILE_SECRET_KEY`、`TURNSTILE_ALLOWED_HOSTNAMES` 和 `AUTH_CAPTCHA_TIMEOUT_SECONDS` 不再读取。发布必须同步后端、登录 HTML、滑块 JS/CSS 和 `AUTH_CAPTCHA_PROVIDER=slider`；回滚同时恢复旧代码和旧配置。详见 [滑块验证协议与验收](../self-hosted-slider-verification.md)。

### CAPTCHA `action` 用途绑定

这不是独立环境变量，而是部署验证时必须理解的协议约束。密码登录固定使用 `login`；短信发送使用 `sms_register`、`sms_login`、`sms_bind_phone`、`sms_password_reset`；受开关限制的旧注册入口使用 `register`。创建挑战、核对拼图和消费凭证的 action 必须完全相同；跨用途、跨浏览器或跨 IP 复用必须失败。

### `OSTORY_AUTH_RATE_LIMIT_SECRET`

- 用途：对登录身份和来源 IP 做 HMAC 后再组成 Redis 限速键。这样 Redis 管理员或诊断快照不会直接看到用户名、手机号或 IP。
- 必填条件：生产必填，至少 32 个字符；必须与 JWT、验证码、API 配置加密密钥不同。
- 格式：高熵随机字符串。它不是 Redis 密码，也不是 CAPTCHA Secret。
- 安全：泄露不会直接授予登录权限，但会降低限速键的隐私保护；轮换会让旧窗口键自然失效并从新键重新计数。
- 验证：测试 Redis 键只含固定前缀和摘要，不含明文身份/IP；日志也不得输出完整键与原始身份的组合。
- 生效：重启全部后端实例。多实例必须使用同一值，否则每个实例会形成不同的限速桶。

### `AUTH_LOGIN_RATE_LIMIT_ENABLED`

- 用途：启用密码登录限速。
- 默认：`true`。
- 生产约束：生产环境不能设置为 `false`；应用会拒绝启动。WAF 或 CDN 限速只能作为额外一层，不能替代应用层按账号和 IP 的联合限制。
- 失败行为：生产运行时 Redis 不可用则认证入口返回 503，不能退化成不限速登录；开发环境可在没有 Redis 时跳过，便于本地页面开发。
- 生效：重启后端。

### `AUTH_LOGIN_RATE_LIMIT_WINDOW_SECONDS`

- 用途：密码登录计数窗口。
- 默认和边界：默认 900 秒，允许 60 到 86400 秒。窗口内计数保存在 Redis，并设置相同 TTL。
- 风险：过短容易被低速爆破绕过，过长会增加误封持续时间。修改时必须结合 CAPTCHA、账号数量、共享出口 NAT 和告警策略压测。
- 验证：超过阈值后返回 HTTP 429 和 `Retry-After`，TTL 到期后恢复；不能通过大小写、手机号空格或常见格式变化绕过身份桶。
- 生效：重启后端；已有 Redis 键仍按创建时 TTL 到期。

### `AUTH_LOGIN_RATE_LIMIT_IDENTITY_ATTEMPTS`

- 用途：同一规范化用户名或手机号在一个窗口内允许的密码登录尝试次数。
- 默认和边界：默认 10，代码限制为 3 到 1000。
- 行为：每次密码登录（包括 CAPTCHA 失败）都会先计数；密码认证成功后清除身份桶。来源 IP 桶不会因某个账号成功而清除，防止攻击者用自己的正确账号重置整个 IP 限制。
- 风险：值过高削弱账号保护，值过低会造成用户输错几次即等待。调整必须记录理由并用自动化验证 429 边界。
- 生效：重启后端。

### `AUTH_LOGIN_RATE_LIMIT_IP_ATTEMPTS`

- 用途：同一来源 IP 在一个窗口内允许的密码登录总尝试次数，用于限制攻击者轮换用户名。
- 默认和边界：默认 100，代码限制为 10 到 10000。
- 风险：学校、企业、运营商 NAT 可能让多人共享 IP，因此默认值高于账号阈值。它不能替代反向代理连接限制、CDN 防护和异常告警。
- 代理要求：只有在反向代理可信且正确覆盖客户端地址时才使用转发 IP；不要无条件信任互联网客户端提供的 `X-Forwarded-For`。
- 验证：轮换多个不存在账号仍应共同触发 IP 桶；切换 IP 不应清除某个账号的身份桶。
- 生效：重启后端。

### `PUBLIC_FEEDBACK_RATE_LIMIT_ENABLED`

- 用途：限制匿名成片分享页的意见提交，防止刷库、骚扰和存储放大。
- 默认：`true`；生产不允许关闭，设置为 `false` 会拒绝启动。
- 失败行为：生产 Redis 不可用时返回 503 并失败关闭；不会退化成无限提交。
- 验证：超过阈值返回 429 和 `Retry-After`，页面仍可只读访问，反馈内容不会被写入。
- 生效：重启后端。

### `OSTORY_PUBLIC_RATE_LIMIT_SECRET`

- 用途：对分享令牌和来源 IP 做 HMAC 后生成 Redis 键，避免在 Redis 快照中留下明文访客标识。
- 默认：未填写时复用 `OSTORY_AUTH_RATE_LIMIT_SECRET`；若单独填写，至少 32 个字符。
- 安全：专用秘密能隔离认证和公开反馈两个用途，推荐生产单独生成。不得使用 Redis 密码、JWT 密钥或可猜字符串。
- 轮换：旧窗口键自然到期，新请求从新摘要键计数；多实例必须同时切换。
- 生效：重启全部后端实例。

### `PUBLIC_FEEDBACK_VISITOR_WINDOW_SECONDS` / `PUBLIC_FEEDBACK_VISITOR_ATTEMPTS`

- 用途：限制“同一分享令牌 + 同一来源 IP”的意见提交。
- 默认/边界：窗口 600 秒，范围 60–86400；次数 10，范围 1–1000。
- 风险：共享出口可能包含多人，阈值过低会误伤；阈值过高会失去滥用保护。不能用浏览器传来的任意转发头直接认定真实 IP。
- 生效：重启；已有键按原 TTL 到期。

### `PUBLIC_FEEDBACK_SHARE_WINDOW_SECONDS` / `PUBLIC_FEEDBACK_SHARE_ATTEMPTS`

- 用途：限制一个公开分享令牌的总意见量，即使攻击者轮换 IP 仍有总桶保护。
- 默认/边界：窗口 3600 秒，范围 60–86400；次数 100，范围 1–10000。
- 验证：多个来源共同超过总阈值时均返回 429；更换分享令牌不能影响其他作品。
- 生效：重启；已有键按原 TTL 到期。

### `API_CONFIG_ENC_KEY`

- 用途：使用 Fernet 加密数据库中的第三方 API Key。
- 必填条件：只要使用后台保存 API Key，生产就必填。
- 格式：`cryptography.fernet.Fernet.generate_key()` 生成的 URL-safe Base64 Key。
- 安全：Base64 不是加密；缺少此字段时不得静默退回 Base64。密钥丢失会导致已存 API Key 无法解密。
- 备份：与数据库分开加密备份，限制读取人员。
- 轮换：先实现重加密流程，不能直接替换后重启。
- 生效：重启或明确的安全热加载流程。

### `OSTORY_ADMIN_USERNAMES` / `OSTORY_SUPER_ADMIN_USERNAMES`

- 用途：把已经存在的账号一次性写成 `admin` 或 `super_admin` 数据库角色；逗号分隔多个用户名，两个列表重复时 `super_admin` 优先。
- 执行：启动时计算本次配置摘要。所有账号都存在后写入角色，并把完成摘要记录在 `system_settings` 的 `security.admin_bootstrap.v1`；同一配置不会再次恢复后来被降级的角色。
- 首次内置登录：如果引导账号尚不存在，启动阶段保持 pending；账号第一次成功登录并创建用户行后立即再次执行引导。
- 授权边界：后台鉴权只读取 `users.role`，绝不直接把环境变量中的用户名当管理员。
- 安全：成功后立即删除这两个环境变量和 `ADMIN_PASSWORD`，重启并验证仍可按数据库角色进入。不要通过修改摘要记录来恢复权限。
- 失败：任一配置账号缺失时不会写完成摘要；日志只报告缺失数量，不输出密码、Token 或密钥。
- 生效：首次启动或首次成功登录；完成后相同配置永久跳过。

## 6. Worker、队列和健康

公开探针 `GET /health` 只返回整体 `status`，用于负载均衡和进程就绪判断。数据库、迁移、Redis、队列、供应商、处理节点、Worker 和发布元数据只通过受管理员角色保护的 `GET /api/admin/system/health` 返回。不要为了方便监控而重新把详细字段放回匿名接口；监控系统应使用独立管理员凭据或位于受控网络中的安全采集方式。

生产模式默认关闭 `/docs`、`/redoc` 和 `/openapi.json`。这不是用“隐藏路由”代替鉴权，而是减少匿名枚举面；每个业务路由仍必须独立完成认证、角色和对象归属检查。若运维确实需要 OpenAPI，应在离线开发环境生成并审核，不要临时把生产文档入口暴露到公网。

应用统一返回 `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、`Permissions-Policy` 和 Content Security Policy；生产额外返回 HSTS。登录页的滑块仅使用本站 JS/CSS 与图片数据；因页面仍有内联脚本，该页保留内联脚本许可，但不再允许外部验证脚本或 iframe；主 SPA 不允许内联脚本。反向代理可以追加更严格规则，但不得删除应用已返回的安全头。启用 HSTS 前必须确认主域和所有纳入的子域都长期支持 HTTPS，否则浏览器会在有效期内拒绝 HTTP 回退。

### `PUBLIC_BIND_HOST`

- 用途：`deploy/public_main.py` 的后端监听地址。
- 默认：`127.0.0.1`，只接受本机连接。
- 格式：本机拥有的 IPv4、IPv6 或可解析主机名；不要填写 URL、端口或路径。
- 生产建议：反向代理与应用同机时保持 `127.0.0.1`。只有在防火墙、私网路由和反向代理确实分离时才考虑监听私网地址；不要为了省配置直接使用 `0.0.0.0` 暴露到公网。
- 验证：用操作系统端口列表确认进程只监听预期地址，再从不应访问的网段验证连接失败。
- 生效：重启。

### `PUBLIC_BIND_PORT`

- 用途：公开源码后端监听端口。
- 默认：`6006`。
- 格式：1 到 65535 的整数；非法值由入口归一化到允许范围，但部署验收仍应把非法原值视为配置错误。
- 冲突：端口已被占用时进程不能正常监听；不要通过杀死不明进程解决，先确认占用者和服务关系。
- 生产建议：只由本机或受控私网反向代理访问，公网用户只连接 443。
- 生效：重启。

### `ONLINE_PROVIDER_WORKERS_COUNT`

- 用途：公开入口内执行第三方在线模型 API 任务的 Worker 数量。
- 默认与范围：默认 4，运行时限制为 1 到 64。
- 影响：每增加一个 Worker，都可能同时增加供应商请求、数据库连接、Redis 操作、媒体内存、临时盘和出口带宽占用；不是数值越大越快。
- 计费风险：并发过高会造成供应商限流、重复重试或费用突增。先使用测试 Key 和低额度账号，从 1 开始逐级压测。
- 验证：提交少量可识别任务，确认在线队列 pending/processing 变化、扣费只结算一次、429/超时不会制造重复结果。
- 生效：重启；缩容前先等待处理中任务完成。

### `ONLINE_PROVIDER_TASK_MAX_RETRIES`

- 用途：在线供应商任务在最终失败前最多进入的尝试次数。
- 默认与范围：默认 3，最小 1；1 表示第一次失败后不再重试。
- 注意：这是总尝试上限，不是“首次之外再重试多少次”。例如值 3 表示最多尝试三次。
- 幂等要求：只有确认供应商请求和本地扣费/入库链路具备幂等约束时才可提高；对状态不明的超时盲目重试可能重复生成和重复计费。
- 生效：重启 Worker。

### `ONLINE_PROVIDER_TASK_RETRY_DELAY_SECONDS`

- 用途：一次可重试失败后，重新进入在线队列前等待的秒数。
- 默认与范围：默认 10，最小 0；0 会立即重排，不建议用于生产限流故障。
- 调优：固定延迟并不能替代供应商建议的退避策略。应结合 429、超时、单任务最长执行时间和业务等待上限确定。
- 生效：重启 Worker。

### `HEALTH_QUEUE_MAX_AGE_SECONDS` / `HEALTH_PROCESSING_MAX_AGE_SECONDS`

- 位置与用途：可选服务端环境变量，分别限制在线任务等待和处理多久后被健康接口报告为 `stalled`；不是供应商执行超时或重试设置。
- 类型与默认：整数秒，默认分别为 `3600`、`7200`；正整数有效，非整数回退默认，非正数限制为 1 秒，不能用 0 关闭检测。只有严格超过阈值才报告停滞。
- 示例：测试环境可分别设置 `60`、`120`，不要不经评估照搬到生产。生产应考虑供应商排队和实际最长生成时间；过小会把正常长任务报告为异常。
- 验证：在隔离环境检查受管理员保护的健康接口：公开入口查看 `online_queue.status`，完整应用查看 `api_tasks.status`。匿名 `/health` 只返回整体状态；即使 `degraded`，HTTP 状态码仍为 200，因此必须检查 JSON。
- 诊断边界：Redis 在线队列均为空但数据库仍有活动在线任务时报告 `inconsistent`。SQL 与 Redis 是分开读取的，应复核持续性和任务记录。检查只读，不会取消任务、重试生成或修改点数，不要根据一次异常探针自动重新提交付费任务。
- 排查与回滚：先核对单位、配置值、任务时间和供应商状态；误报时恢复原阈值，不能通过清空队列或修改任务状态消除告警。
- 生效：每次探针读取当前进程环境；更改服务环境配置后需按正常维护流程重启应用。不要为调整阈值直接打断正在执行的任务。

### `API_PROVIDER_HEALTH_MONITOR_ENABLED`

- 用途：是否后台检查已配置在线供应商的可用性并把脱敏结果写入 Redis。
- 默认：`true`。
- 风险：健康检查可能产生真实外部请求、额度消耗和供应商审计记录；不理解当前探测类型时不要盲目提高频率。
- 安全：检查结果只在管理员健康接口汇总，匿名 `/health` 不返回供应商名称、Endpoint 或错误正文。
- 生效：重启。

### `API_PROVIDER_HEALTH_INITIAL_DELAY_SECONDS` / `API_PROVIDER_HEALTH_INTERVAL_SECONDS`

- 用途：分别控制启动后第一次供应商检查的延迟和后续检查间隔。
- 默认与下限：初始延迟默认 60 秒、最小 0；间隔默认 300 秒、最小 60 秒。
- 调优：初始延迟用于避免数据库、Redis、迁移和 Worker 同时启动造成峰值；间隔必须结合供应商限额、探测成本和故障发现目标。
- 生效：重启。

### `API_PROVIDER_HEALTH_TTL_SECONDS` / `API_PROVIDER_REAL_GENERATION_HEALTH_TTL_SECONDS`

- 用途：普通连通性结果与真实生成结果在 Redis 中的缓存期限。
- 默认：普通结果 900 秒；真实生成结果 604800 秒（7 天）；两者最小 60 秒。
- 区别：连通成功不等于真实生成成功。真实生成验证成本更高，所以单独保留较长时间；界面和运维记录不得把两种结果混为同一证明。
- 生效：重启监控进程；旧缓存会按原 TTL 自然过期，必要时只能通过受控管理操作清除。

### `API_PROVIDER_HEALTH_CONCURRENCY`

- 用途：一次健康检查批次中并发检查的供应商/模型数量。
- 默认与范围：默认 3，最小 1。
- 风险：值过大会同时消耗外部额度、连接池和出口带宽，并更容易触发 429；先用 1 验证，再依据供应商限制调高。
- 生效：重启。

## 7. 文件和媒体

### `STORAGE_TYPE`

- 用途：选择 `local` 或受支持对象存储实现。
- 必填条件：生产明确填写，不依赖默认。
- 风险：切换不会自动迁移旧文件；必须先做清单、复制、校验和数据库 URL 迁移。
- 生效：重启。

### `STORAGE_BASE_PATH` / `LOCAL_STORAGE_PATH`

- 用途：本地媒体根目录。
- 格式：生产建议绝对路径。
- 安全：目录必须在仓库和 Web 根目录外；服务账号最小 ACL；防路径穿越和符号链接越界。
- 生效：重启；改路径前迁移并校验全部对象。

### `MAX_UPLOAD_SIZE`

- 用途：上传大小上限，单位字节。
- 格式：正整数。
- 代码行为：公开上传入口以分块方式读取，并在刚超过该值时立即返回 413；旧版“全部读入内存后再判断”的行为不再视为合格。
- 安全：后端与反向代理都要限制；还要限制解码后的像素、时长和压缩展开体积。该参数是单请求上限，不是用户总配额；用户总配额必须把“已用字节 + 本次文件字节”一起计算。
- 生效：重启后端，反向代理配置单独重载。

公开前端的图片、视频和在线供应商参考音频都走这个通用上传入口。音频不会被发送到 Ovideo 私有 ComfyUI 节点，也不会由隐藏服务替使用者剪切；供应商支持的格式、时长和大小仍需在对应平台章节再次核对。上传返回的文件必须先登记到数据库，后续在线 Worker 才能在鉴权和路径约束后读取。

### `MEDIA_LIBRARY_BATCH_DOWNLOAD_MAX_BYTES`

- 用途：限制一次素材库批量下载中所有实际入包文件的未压缩字节总和，防止已登录用户通过大量素材压垮后端内存、临时磁盘或压缩 CPU。
- 默认：536870912（512 MiB）。允许范围为 1048576（1 MiB）到 10737418240（10 GiB）；无效值回退到默认值，越界值会被夹到边界。
- 计算方式：后端先逐项执行素材可见性检查，再读取数据库文件记录，并把物理路径重新解析到允许媒体根目录；只有通过这些检查的普通文件才计入总和。达到上限后返回 413，不生成不完整的下载包。
- 内存行为：ZIP 前 8 MiB 使用内存缓冲，超过后自动写入操作系统临时文件，并以分块方式返回。该 8 MiB 是实现安全阈值，不是业务容量，也不能用本参数修改。
- 文件名安全：ZIP 条目始终转换为单层文件名，删除控制字符和路径分隔符；素材标题中的 `../`、反斜杠或绝对路径不会进入压缩包目录结构。
- 容量评估：本参数限制未压缩输入总量，不等于最终 ZIP 大小。设置值必须同时小于临时磁盘可用空间，并乘以允许的并发下载数评估最坏占用；反向代理还应设置并发、响应超时和连接速率限制。
- 验证：至少测试根目录内文件、根目录外数据库路径、符号链接逃逸、包含 `../` 的标题、恰好等于上限和超过上限 1 字节；越界路径必须被跳过，超总量必须返回 413。
- 生效：重启后端。

### `PUBLIC_VIDEO_CROP_MAX_SOURCE_BYTES`

- 用途：公开版 FFmpeg 裁剪允许读取的单个源视频最大字节数。
- 默认：536870912（512 MiB）；允许范围 1048576 到 2147483648 字节，越界值会被夹到边界。
- 安全边界：只在当前用户通过文件访问检查、数据库记录的 `file_type` 为 `video`、且物理文件位于配置媒体根目录之后检查。它不是上传上限，也不是用户总配额。
- 容量评估：应小于可用临时/持久磁盘预算，并结合同时裁剪任务数、源视频码率和输出码率计算；不要因为单个大文件失败就直接调到上限。
- 验证：用边界内视频成功裁剪；超过值返回 422；数据库外路径、软删除记录、其他用户文件和 `comfyui://` 路径返回 404 且不泄漏真实路径。
- 生效：重启公开后端。

### `PUBLIC_VIDEO_CROP_MAX_DURATION_SECONDS`

- 用途：限制一次公开版视频裁剪片段的最长秒数。
- 默认：3600 秒；允许范围 1 到 86400 秒。
- 校验：`start_time` 必须大于等于 0，`end_time` 必须大于 `start_time`，两者差值不得超过本参数。无效请求在读取文件和启动 FFmpeg 前拒绝。
- 风险：时长上限不等于 CPU 时间上限；高分辨率、高帧率和复杂编码仍可能更慢，必须与下方超时共同设置。
- 生效：重启公开后端。

### `PUBLIC_VIDEO_CROP_TIMEOUT_SECONDS`

- 用途：公开版单次 FFmpeg 裁剪进程最长运行秒数。
- 默认：180 秒；允许范围 10 到 1800 秒。
- 失败行为：超时会终止等待并返回通用错误，临时文件会删除；不得把 FFmpeg 原始命令、服务器路径或完整 stderr 返回用户。
- 调优：先在与生产相同的 CPU、磁盘和典型视频上测量 P95/P99，再保留合理余量。超时过短产生假失败，过长会让恶意或异常媒体长期占用进程槽。
- 生效：重启公开后端。

### `MAX_IMAGE_SOURCE_PIXELS`

- 用途：限制上传或处理图片解码后的像素总数，防止小字节、大尺寸的图片解压炸弹耗尽内存。
- 默认：80000000 像素；应按允许的最大长边、并发和图像库内存峰值压测调整。
- 格式：正整数。它限制宽乘高，不等同于文件字节数，也不等同于输出分辨率。
- 验证：普通图片通过；高压缩超大尺寸图片在完整解码前被拒绝；错误响应不包含服务器路径或解析堆栈。
- 生效：重启执行图片校验的进程。

### MAX_REMOTE_IMAGE_DOWNLOAD_BYTES

- 用途：后端从第三方供应商下载生成图片时允许的最大响应体，单位字节。
- 默认：52428800（50 MiB）。
- 格式：正整数；零、负数和非整数属于配置错误。
- 安全：同时检查可信的 Content-Length 和实际接收字节；不能只信任响应头。超过上限时任务失败，不保存截断文件。
- 注意：该值限制“远程下载”，不替代 MAX_UPLOAD_SIZE、图片像素上限和供应商侧限制。
- 生效：重启执行下载的后端进程。

### MAX_PROVIDER_IMAGE_INPUT_BYTES

- 用途：限制发送给在线视频供应商的每张输入图片，单位字节。它覆盖数据库登记的本地媒体、`data:image/...` 数据 URI 和公网 HTTP(S) 图片三种输入方式。
- 默认：20971520（20 MiB）。
- 格式：正整数；未设置时采用默认值，零、负数和非整数应当视为部署配置错误并在上线验收中纠正。
- 与其他参数的区别：`MAX_REMOTE_IMAGE_DOWNLOAD_BYTES` 限制“从供应商取回生成结果”；本参数限制“准备发送给供应商的参考图”。二者方向相反，必须分别配置。
- 安全行为：本地文件必须先在数据库登记，并解析到允许的媒体根目录；远程地址必须是公网 HTTP(S)，禁止自动跟随重定向，并同时校验声明长度和实际字节数；所有来源都必须通过安全图片解码和像素限制。
- 容量评估：至少按“单图上限 × 单任务最大参考图数 × 在线 Worker 并发数”估算内存、临时盘和出口流量，不要仅根据单张图片大小设置。
- 生效：重启处理在线供应商任务的 Worker。

### MAX_PROVIDER_AUDIO_INPUT_BYTES / MAX_PROVIDER_VIDEO_INPUT_BYTES

- 用途：限制为了在线供应商请求而转成内联数据 URI 的单个本地音频或视频，单位字节。
- 默认：两个参数当前都为 20971520（20 MiB），与旧在线 Worker 已接受的最大内联媒体体积一致。
- 何时使用：数据库登记的私有音频/视频不能由第三方平台直接携带本站会话访问，因此 Worker 会在权限校验后以内联数据 URI 发送；公网 URL 只执行公网地址校验并交由供应商抓取，不在本机下载。
- 安全：数据库记录的 MIME 必须与 `audio/*` 或 `video/*` 类别一致，物理路径必须位于允许媒体根目录；必须在读取文件前检查文件大小，读取后再检查实际字节数。软删除或没有数据库记录的本地路径不得恢复使用。
- 容量评估：Base64 通常增加约三分之一体积；还要叠加 HTTP 客户端缓冲、并发 Worker 数和供应商请求上限。若平台允许的输入大于默认值，也不要盲目调高，先测算进程内存和反向代理请求体上限。
- 与结果下载的区别：这两个参数限制发送给供应商的输入；`MAX_REMOTE_AUDIO_DOWNLOAD_BYTES`、`MAX_REMOTE_VIDEO_DOWNLOAD_BYTES` 限制取回的结果。四者不能互相替代。
- 生效：重启处理在线供应商任务的 Worker。

### MAX_REMOTE_AUDIO_DOWNLOAD_BYTES

- 用途：远程语音、配音参考和混音输入的单文件下载上限，单位字节。
- 默认：104857600（100 MiB）。
- 风险：值过小会拒绝长音频，值过大会放大磁盘、带宽和并发占用。应根据最长合法音频、码率和并发量计算，并在反向代理/出口网关同步限制。
- 网络要求：远程地址必须为公网 HTTP(S)，且当前实现拒绝自动跟随下载重定向；需要使用供应商给出的最终受信下载 URL。
- 生效：重启执行音频任务的后端进程。

### MAX_REMOTE_VIDEO_DOWNLOAD_BYTES

- 用途：第三方生成视频或视频配音参考的单文件下载上限，单位字节。
- 默认：1073741824（1 GiB）。
- 风险：该值乘以最大并发即是潜在带宽/磁盘压力的重要部分；生产必须配合任务并发、用户配额、磁盘告警和下载超时设计。
- 网络要求：远程地址必须通过公网地址校验；自动重定向被拒绝，防止初始公网 URL 把服务端引向回环、私网或云元数据地址。
- 生效：重启执行视频任务的后端进程。

### MAX_EXTRACTED_REFERENCE_AUDIO_BYTES

- 用途：从视频中提取“参考配音”后，允许写入媒体库的单个音频文件上限，单位字节。
- 默认：52428800（50 MiB）。它限制 FFmpeg 产出的音频，不是源视频大小；源视频仍由 `MAX_REMOTE_VIDEO_DOWNLOAD_BYTES` 单独限制。
- 安全行为：程序在读取音频进内存前先检查文件大小，读取后再次核对实际字节数。超过上限时整个提取任务失败，不会把截断内容作为成功结果入库。
- 容量评估：应按最长允许视频、音频码率和同时提取任务数计算；调高源视频上限并不会自动调高本参数。
- 验证：准备一个超过阈值的受控测试输出，确认任务明确失败、数据库中没有成功文件记录、临时目录最终清理。
- 生效：重启执行视频参考音频提取的后端进程。

### MAX_PROVIDER_AUDIO_OUTPUT_BYTES

- 用途：限制在线音频供应商直接返回并由 Worker 保存的单个音频结果，单位字节；当前 MiniMax 同步 TTS 的十六进制结果和兼容文件回退路径都会执行该限制。
- 默认：104857600（100 MiB）。
- 与下载上限的区别：`MAX_REMOTE_AUDIO_DOWNLOAD_BYTES` 控制额外 HTTP 下载流；本参数控制供应商 JSON 内嵌音频解码结果及 Worker 最终持久化前的字节体积。即便二者默认相同，也必须理解为不同信任边界。
- 安全行为：十六进制字符串在解码前按“两位十六进制约等于一字节”预检，解码后再次精确检查；兼容本地文件在 `read_bytes()` 前先检查磁盘大小，读取后再复核。
- 容量评估：供应商使用十六进制嵌入 JSON 时，响应正文至少约为音频二进制的两倍，还会叠加 JSON 解析峰值；并发预算不能只按 100 MiB 计算。
- 生效：重启在线供应商 Worker。

### `MINIO_ENDPOINT`

- 用途：MinIO 主机和端口。
- 必填条件：`STORAGE_TYPE=minio` 时必填。
- 格式：按客户端约定的 `host:port`，不要混入无关路径。
- 安全：优先私网和 TLS。
- 生效：重启。

### `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY`

- 用途：MinIO 凭据。
- 必填条件：MinIO 模式必填。
- 安全：不得使用 `minioadmin` 或任何默认凭据；只授予目标 Bucket 所需权限。
- 启动行为：生产 MinIO 模式会拒绝空凭据以及任一值为 `minioadmin` 的配置，不会替操作者补默认凭据。
- 生效：重启；轮换先验证新凭据。

### `MINIO_BUCKET`

- 用途：媒体 Bucket。
- 格式：符合对象存储命名规则。
- 安全：默认私有，禁止匿名列表和匿名读取；媒体通过授权接口或短期签名 URL 访问。
- 生效：重启。

### `MINIO_SECURE`

- 用途：是否用 TLS 连接 MinIO。
- 格式：布尔。
- 安全：跨主机/跨网络生产通信必须为 `true` 并验证证书；程序会拒绝非回环地址上的生产明文 MinIO。只有同机 `localhost` / `127.0.0.1` / `::1` 连接可显式使用 `false`，仍建议在反向代理或服务网格中提供加密边界。
- 生效：重启。

### `CDN_ENABLED` / `CDN_BASE_URL`

- 用途：可选 CDN。
- 风险：私有媒体必须用短期签名和正确缓存键；不能把长期 JWT 放进 CDN URL；清除缓存与删除流程必须联动。
- 生效：重启。

### `CDN_ACCESS_KEY` / `CDN_SECRET_KEY`

- 用途：CDN 管理凭据。
- 安全：只给所需刷新/签名权限，不得返回前端或写日志。
- 生效：重启。

### `FFMPEG_BIN` / `FFPROBE_BIN`

- 用途：指定 FFmpeg/FFprobe 可执行文件。
- 格式：受信任绝对路径。
- 安全：不得指向用户可写目录；升级后重新验证媒体处理。
- 生效：重启执行相关任务的进程。
- 公开版裁剪只使用 `FFMPEG_BIN`；`FFPROBE_BIN` 供其他媒体能力使用。公开后端通过系统可执行文件解析确认 `FFMPEG_BIN` 存在，随后以固定参数数组调用，不把用户输入拼接成 Shell 命令。

### `AUDIO_UPLOAD_DIR`

- 用途：音频上传或处理目录。
- 安全：同本地媒体目录；不得位于公开静态目录或仓库。
- 生效：重启。

验证短信时必须检查：手机号规范化、用途隔离、验证码哈希存储、过期、单次消费、IP/手机号/设备限速、日上限、账号枚举政策和供应商失败映射。前端提交的 `captcha_verification` 必须由后端真实校验；仅有字段但不验证不构成验证码防护。

## 10. 微信支付 APIv3

支付功能默认关闭。只有自行取得微信支付商户资格、完成应用与商户绑定、理解资金结算和退款责任，并在隔离测试环境验证签名、回调、金额和幂等后才应开启。开源发布方不代办商户、证书、备案、结算、退款或争议处理，也不会接触使用者的资金和密钥。

### `OSTORY_WECHAT_PAY_ENABLED`

- 用途：启用微信支付 Native 扫码充值入口。
- 默认：`false`。未启用时不得创建支付订单，但页面可以读取“当前未启用”的公开选项状态。
- 格式：只有不区分大小写的 `true` 才启用；生产不要用含糊值。
- 上线前：确认数据库迁移包含支付订单和唯一交易约束，回调域名已使用 HTTPS，退款/对账/客服流程已建立。
- 生效：重启。

### `OSTORY_WECHAT_PAY_APP_ID`

- 用途：调用支付的应用 AppID，必须与微信支付商户平台绑定的应用一致。
- 不是：商户号、APIv3 密钥、公众号名称或小程序名称。
- 常见错误：复制了未绑定的另一个应用 AppID，导致下单或回调中的 `appid` 校验失败。
- 安全：AppID 不是私钥，但仍应作为部署配置管理，不要随意写进截图或问题报告。

### `OSTORY_WECHAT_PAY_MCH_ID`

- 用途：微信支付商户号 `mchid`。
- 格式：按商户平台显示值原样填写，不添加空格、说明文字或引号内容。
- 绑定：必须与 AppID、商户私钥、证书序列号、APIv3 密钥属于同一商户体系。
- 验证：下单返回和回调解密后的商户号必须与配置完全一致；不一致时停止入账。

### `OSTORY_WECHAT_PAY_MERCHANT_SERIAL_NO`

- 用途：商户 API 证书序列号，用于告诉平台请求由哪一张商户证书签名。
- 不是：微信支付平台公钥 ID，也不是证书文件名。
- 轮换：商户证书更新时，私钥路径和序列号必须成对切换；先在测试请求验证，再废弃旧证书。
- 常见错误：序列号大小写/空格错误，或证书与私钥不是一对。

### `OSTORY_WECHAT_PAY_MERCHANT_PRIVATE_KEY_PATH`

- 用途：商户 API 私钥 PEM 文件的绝对路径。
- 文件要求：内容应包含标准 `PRIVATE KEY` PEM 标记，并与商户证书配对。
- 权限：只允许运行服务账号读取；目录不能被 Web 服务、普通用户或构建流程读取。不要把 PEM 内容直接写入环境变量、Git、镜像、日志或管理后台 JSON。
- 路径：使用部署机器上的实际路径；公开示例只能写 `<FILL_ME_WITH_ABSOLUTE_SECRET_PATH>`。
- 轮换：原子替换受限文件或切换到新路径，重启后验证，再安全撤销旧材料。

### `OSTORY_WECHAT_PAY_API_V3_KEY_PATH`

- 用途：存放 APIv3 密钥的文本文件路径，用于解密支付回调资源。
- 格式：文件去除首尾空白后必须正好是 32 字节；它不是 APIv2 Key，不是证书密码，也不是平台公钥。
- 权限与备份：按资金级秘密保护，只允许服务账号读取，单独加密备份；泄露后立即在商户平台轮换并评估历史回调风险。
- 失败表现：长度错误或无法读取时，启用支付的请求会失败关闭，不应回退为不验签。

### `OSTORY_WECHAT_PAY_PUBLIC_KEY_ID`

- 用途：微信支付平台公钥 ID，用于选择验证回调签名的平台公钥。
- 不是：商户证书序列号。两者由不同主体签发，不能互换。
- 轮换：平台公布新公钥时，公钥 ID 和公钥文件必须同时更新；在旧材料失效前完成双环境验证。

### `OSTORY_WECHAT_PAY_PUBLIC_KEY_PATH`

- 用途：微信支付平台公钥 PEM 文件的绝对路径，用于验证响应与回调签名。
- 文件要求：内容应包含标准 `PUBLIC KEY` PEM 标记；必须从微信支付官方渠道取得并核验指纹/ID。
- 禁止：不要从论坛、聊天附件或第三方镜像下载公钥；不要为了排障关闭签名验证。

### `OSTORY_WECHAT_PAY_NOTIFY_URL`

- 用途：微信支付服务器可访问的支付结果通知地址。
- 格式：完整公网 HTTPS URL；当前路由通常对应 `https://<你的域名>/api/payments/wechat/notify`。
- 网络：只能开放这一条必要回调路径，不要把数据库、Redis 或后台管理端口一并暴露。
- 代理：必须原样转发请求体和微信签名相关请求头；任何解析、重新编码或截断都可能导致验签失败。
- 验证：分别测试签名正确、签名错误、重复通知、乱序通知、金额不符和未知订单。只有验签、解密、商户/AppID、订单号、金额和状态全部一致时才能入账。

### `OSTORY_WECHAT_PAY_ORDER_EXPIRE_MINUTES`

- 用途：新支付订单的有效分钟数。
- 默认与范围：默认 30，允许 1 到 120。虽然读取器会对部分非法整数回退，正式验收应把任何非法输入视为配置错误。
- 业务影响：太短会导致用户扫码时已过期；太长会增加未支付订单和价格策略变更的处理复杂度。
- 生效：重启；只影响新订单，不应篡改已创建订单的过期时间。

### `OSTORY_WECHAT_PAY_MAX_POINT_AMOUNT`

- 用途：限制单笔充值可以兑换的最大创作点数。
- 默认：1000000；必须根据反欺诈、资金风险、退款流程和业务定价主动下调到适合自己的值。
- 安全：浏览器提交的金额或点数都不可信。服务端必须重新报价、验证整数范围，并在已验签支付金额与本地订单金额完全一致后入账。
- 变更：先核对前端显示、服务端报价和财务制度；不能只改界面上限。

微信支付上线验收必须至少覆盖：私钥/公钥权限、证书和平台公钥轮换、回调重放、重复通知幂等、金额和币种核对、未知订单、过期订单、已关闭订单、数据库事务失败、积分只入账一次、退款后的业务处理、对账差异、日志脱敏和告警。测试时使用受控小额订单，不在生产中用真实用户账号做破坏性验证。

## 11. 第三方模型供应商通用字段

管理后台一张 API 配置卡包含以下字段：

### `name`

- 管理员可读名称；应说明平台、计费通道和用途。
- 不参与供应商认证，不要放 Key 尾号以外的敏感信息。

### `provider`

- 代码使用的供应商标识，必须来自支持列表：`gemini-text`、`gemini-image`、`deepseek`、`doubao`、`minimax`、`sora2`、`veo`、`dashscope`、`seedance`、`laozhang-gpt-image`、`laozhang-sora2`。
- 不是任意显示文本；拼写错误会导致路由或环境变量映射失败。

### `endpoint`

- 完整 HTTPS API 基址或对应操作地址。
- 必须核对平台地区、国内/国际站、按量/套餐通道和接口版本。
- 禁止使用包含用户信息、密码或 API Key 的 URL。
- 自定义网关应经过所有权、TLS、日志、隐私和 SSRF 审计。
- 生产默认要求 HTTPS，并要求 DNS 解析结果全部是公网地址；HTTP、回环、私网、链路本地和云元数据地址默认拒绝。
- 请求执行阶段禁止自动跟随重定向。初始 URL 通过校验不代表重定向目标可信；若平台返回 3xx，应把经过验证的最终官方地址直接配置为 Endpoint。

### `api_key`

- 平台颁发的服务端 Key。
- 只在后端写入，数据库必须用 `API_CONFIG_ENC_KEY` 真加密。
- 管理接口读取时只能返回“已配置”和掩码，不能返回明文。

### `model_name`

- 该卡默认模型 ID。
- 必须使用平台实际接受的精确 ID，不要把 UI 展示名称当成模型 ID。
- 更换会影响新任务；历史任务必须保存实际供应商和实际模型快照。

### `model_bindings`

- JSON 数组，把一个供应商 Key 绑定到多个操作/模型/使用范围。
- 每项至少包含 `operation`、`model_name`，需要时包含 `scope`。
- `scope=workflow` 表示流程化制作，`scope=studio` 表示自由创作。
- 禁止同一作用域/操作出现冲突绑定；测试后再启用。

### `proxy_mode`

- `direct`：后端直连供应商；
- `custom`：使用 `custom_proxy`；
- 其他模式只有代码明确支持时才能使用。
- 代理配置不等于 Endpoint；代理能看到流量元数据，必须可信。

### `custom_proxy`

- 自定义 HTTP(S) 代理 URL，仅在 `proxy_mode=custom` 时使用。
- 凭据不应直接暴露在 UI、日志或导出中。
- 必须防止普通用户控制该值，否则可能形成 SSRF/内网访问。

### `ALLOW_INSECURE_PROVIDER_ENDPOINTS` / `ALLOW_PRIVATE_PROVIDER_ENDPOINTS`

- 用途：分别允许生产供应商 Endpoint 使用 HTTP、允许解析到回环或私网地址。
- 默认：均为 `false`。
- 使用边界：只适用于部署者自行审计的企业内网兼容网关。启用前必须确认网关所有者、TLS/网络隔离、日志保留、认证转发、DNS 和出站访问范围。
- 风险：两个开关会放宽携带供应商密钥的服务端出站请求；误配可造成凭据泄露或 SSRF。不能由普通管理员卡片或用户请求动态开启。
- 生效：重启后端；关闭后重新保存并健康检查每张供应商卡。

### `ALLOW_PRIVATE_API_PROXIES`

- 用途：允许生产 `custom_proxy` 解析到私网地址。
- 默认：`false`。
- 风险：代理可看到目标域名、请求元数据，并可能看到解密后的请求内容。只允许组织控制、经过审计的代理；不得指向用户提供的地址。
- 注意：当前开关不允许带 URL 凭据，不代表代理自动安全；代理认证应使用受控、不会被管理接口回显的机制。
- 生效：重启后端。

### `request_template`

- 供应商额外请求参数 JSON。
- 只允许白名单字段；不能允许覆盖认证头、任意 URL、用户 ID、计费主体或安全参数。
- MiniMax 的 `group_id`、`provider_access_mode` 等扩展字段存放于此。

### `headers`

- 额外 HTTP Header JSON。
- 最多 64 个字段；名称必须符合 HTTP Header token 语法；值只允许字符串、数字或布尔标量，单值最多 8192 个字符。
- 值中禁止回车、换行和 NUL，防止请求头注入。
- 禁止覆盖 `Host`、`Content-Length`、`Transfer-Encoding`、`Connection`、`Proxy-Connection`、`TE`、`Trailer`、`Upgrade`、`Keep-Alive` 等由 HTTP 客户端管理的头。
- `Authorization` 仅可由明确支持该平台认证格式的适配器处理；不要在通用额外头中重复保存主 API Key。
- 导入、创建、更新、健康检查和运行时加载必须应用同一校验，不能只在前端做限制。

### `category`

- 能力分类：空字符串、`text`、`image`、`video`、`audio`。
- 必须与供应商/模型能力一致。

### `enabled`

- 是否参与运行时选择。
- 禁用不等于删除；历史任务仍应显示当时实际模型。
- 启用前先做非计费健康检查，再用低成本真实请求验证。

## 12. 通用供应商环境变量派生规则

每个供应商主 Key 可派生：

- `<PREFIX>_API_KEY`：主 Key；
- `<PREFIX>_ENDPOINT`：Endpoint；
- `<PREFIX>_MODEL`：默认模型；
- `<PREFIX>_PROXY_MODE`：代理模式；
- `<PREFIX>_CUSTOM_PROXY`：自定义代理；
- `<PREFIX>_MODEL_STUDIO`：自由创作范围模型覆盖（代码支持时）。

操作级覆盖采用 `<PROVIDER>_<OPERATION>_API_KEY`、`<PROVIDER>_<OPERATION>_ENDPOINT` 和对应代理字段。操作名中的连字符会转换为下划线并大写。

后台数据库配置优先用于集中管理。环境变量仅用于引导、兜底或使用者明确选择的无数据库配置方式。不要让两个来源长期配置不同值；运行状态页应只显示来源名称和掩码，不能显示秘密。

## 13. 发布前配置自检

上线前逐项确认：

- 生产环境没有任何 `<FILL_ME...>`；
- 没有默认管理员、默认 MinIO 凭据、空数据库/Redis 密码；
- 三个核心安全密钥互不相同；
- CORS 只有真实 HTTPS Origin；
- 前端环境和构建产物没有供应商 Key；
- 后台 API Key 使用 Fernet 加密，不是 Base64；
- 所有 Endpoint 都是预期平台和地区；
- 代理、邮件、短信和对象存储凭据均为最小权限；
- 日志、健康接口和错误响应不泄露内部结构或第三方原始响应；
- 配置变更、密钥轮换和恢复过程都已演练。
