# 视频反推运行契约

## 入口与依赖边界

`video_reverse_routes.create_video_reverse_router` 接收服务提供器，使用 `get()` 取得任务服务、`get_queue()` 取得任务队列。公开入口注入在线任务服务，集群入口注入现有任务服务；共享路由不得导入私有任务实现。

保留 `/api/video-reverse` 下的估价、创建、列表、详情、取消、重试操作。任务类型仍为 `video_reverse_prompt`；分段描述、分镜提示词和关键帧的返回字段不变。视频分析使用配置的视觉模型和 FFmpeg，不依赖本地 GPU 节点。

## 权限与持久化

- 来源视频必须由当前账号拥有，或位于其可读取的项目；不以客户端传入的用户标识授权。
- 可读来源不代表可写目标。创建和重试先验证目标项目、剧集的成员权限及二者一致性，再探测视频或冻结点数。仅传剧集时解析并保存其所属项目。
- 每段抽帧数支持 1–3，保存在已有 `metadata.frames_per_segment`，重试沿用原值；历史记录没有该字段时沿用旧默认值 2。仅支持已有的均匀抽帧策略。
- 重试通过旧任务 ID 与失败/取消状态进行条件更新；只有抢占成功的请求可以冻结和入队。
- Worker 的进度和终态写入绑定当前队列任务 ID；旧尝试不能覆盖新尝试。
- 分析结果、分段替换及完成状态在同一数据库事务提交。分段保存中途失败必须保留此前结果，不能留下半套分镜。
- 已完成尝试的重新投递复用已有结果，不重复分析和扣费。
- 结果提交后结算失败保留结果与冻结点数。所有者读取详情或 Worker 重新投递时，仅重试仍处于冻结状态的原账单，不重新报价、冻结或分析；结算已提交但响应丢失也不会重复扣费。这是访问/投递触发的恢复，不是后台定时对账。

## 失败和取消

先冻结点数，再入队；入队失败进行补偿。无可分析画面、视觉请求失败、空分析结果均是任务失败，不能以空白结果标记成功并收费。失败由管线释放冻结，Worker 不自动重新执行已退款的尝试；手动重试重新授权、报价并冻结。

取消遵守实际队列的提交保护：尚未提交的任务可以取消并退款；已经进入供应商请求的任务可能返回 409，保留冻结并等待结果。不能为了让取消按钮返回成功而绕过这一保护。

## 验证范围与后续审计

`test_public_video_reverse.py` 通过公开 HTTP 路由、实际账号/DAO/队列/账本覆盖正常任务、权限拒绝、参数与重试、失败退款、过期尝试、重复投递及事务回滚。结算故障测试分别覆盖提交前失败、提交后响应丢失以及两种恢复入口，检查原冻结与消费流水各只有一条。抽帧和付费视觉响应由测试替代，不证明真实编解码或供应商质量。

运行验收还须在真实隔离 PostgreSQL、Redis 和 HTTP 服务中覆盖公开、agent-only、mixed 三种入口模式。测试并发重试时明确停止测试 Worker，避免用模拟视频触发真实供应商；不得据此宣称完成付费生成实测。

这组回归不是完整开源发布验收。FFmpeg 进程超时/取消与临时目录回收、无人再次访问/投递时的长期冻结对账、完整公开候选安装及其他业务模块的导入缺口仍需分别审计。不得把入口导入成功或该组测试通过等同于全平台可发布。
