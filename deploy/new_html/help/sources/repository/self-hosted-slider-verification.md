# 自托管滑块安全验证

登录、注册发短信、验证码登录发短信、绑定手机号、找回密码共用本站拼图验证。
图片在本站后端即时生成，不加载外部脚本、图片或 iframe，不需要 Cloudflare。

## 配置与发布

- `AUTH_CAPTCHA_REQUIRED=true`：生产开启安全验证。
- `AUTH_CAPTCHA_PROVIDER=slider`：正式发布必须与新代码一起修改；旧的 `turnstile` 值会被拒绝，不会静默降级。
- `OSTORY_CAPTCHA_SECRET`：建议独立的高熵随机秘密，至少 32 字符。未指定时允许使用现有 `OSTORY_VERIFICATION_CODE_SECRET`，但通过独立 HMAC 域隔离派生浏览器绑定与限速摘要；秘密不返回前端。
- 原 `TURNSTILE_*` 配置不再被读取，可以在正式切换时移除。不要关闭全站其他安全策略。
- 依赖已有 Pillow、Redis；不新增服务、数据库表、GPU 任务或外部验证调用。
- 发布时一起包含 `login.html`、`static/js/slider-captcha.js`、`static/css/slider-captcha.css`、认证路由、服务代码和安全头改动，避免新旧前后端混用。

遵循项目发布流程：本地测试和构建、备份原镜像与环境配置，再切换应用；不得在生产构建。若回滚，旧镜像及旧 CAPTCHA 环境必须一并恢复。此文档不是部署授权。

## 协议与安全边界

1. `GET /api/auth/captcha-config` 设置 HttpOnly、SameSite=Strict 的浏览器会话 Cookie；生产附加 Secure。响应禁止缓存。
2. `POST /api/auth/captcha/challenge` 返回随机拼图和挑战 ID；正确横坐标只保存在 Redis。挑战绑定浏览器会话、请求来源 IP 和操作用途，有效期 120 秒。
3. `POST /api/auth/captcha/check` 由服务端比较偏移，允许 5px 误差；同一挑战只允许一次作答。通过后签发有效期 60 秒的一次性随机凭证。
4. 原登录/发短信 API 仍验证 `captcha_verification`，原子消费正确会话、IP、用途的凭证。重复、过期、跨会话或跨用途使用都不通过。
5. 挑战和作答分别限制每 IP 每分钟 30 次、全站每分钟 600 次。Redis 故障时拒绝验证，不放行；现有密码尝试、手机短信冷却、日上限和短信全站预算保持不变。

滑块不是账户身份认证，也不能保证抵御专业视觉识别或人工打码。需要与密码、短信验证码、流量限速和服务商预算一起使用；不得以滑块成功替代手机号验证。日志不记录验证码、拼图答案、凭证、Cookie 或原始手机号。

## 交互与验收

- 点击获取验证码时自动弹出拼图，通过后只发送一次；等待验证/发送期间禁止重复提交。
- 鼠标或触屏拖动，松手校验；也支持方向键和回车，或点击“确认对齐”。
- 拼图失败、过期或超时可换一张；关闭弹窗不清空手机号、密码等输入。
- 只有登录页显示“密码登录/验证码登录”切换，注册、绑定、找回密码不显示。
- 回归验证所有认证入口、发送失败、重复点击、令牌重放、跨浏览器/用途、Redis 故障及无缓存响应。
- 自动化测试使用测试 Redis 和假短信发送器，不向用户手机发送短信。正式送达仍需发布后由用户完成真实验证并确认收信。

## 本地浏览器回归

`node deploy/scripts/test_slider_browser.mjs` 使用真实登录 HTML、滑块资源、生产同款 CSP 和仅监听回环地址的模拟 API。设置 `PYTHON_PATH` 为含 Pillow 的 Python、`BROWSER_PATH` 为已安装 Chromium/Edge（常见路径自动查找），可通过 `VERIFY_OUT_DIR` 指定截图目录。

脚本覆盖桌面鼠标拖动、移动端触屏拖动、松手自动校验、模拟短信只请求一次、注册页隐藏登录切换而登录页保留，以及无外部网络请求。它不会连接短信供应商、注册账户或访问生产服务。浏览器使用独立临时配置目录，不触碰用户现有浏览器会话。
