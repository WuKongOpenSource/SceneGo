# 后台点数管理运行契约

## 入口与职责

公开入口与完整应用入口共用 `deploy/routers/admin_credits.py`，统一挂载在 `/api/admin`。路由依赖身份、计费、账本和支付订单存储，不导入节点、调度或部署实现。前端现有请求路径、主要请求字段及响应字段保持不变。

| 操作 | 路径 | 所需角色 |
| --- | --- | --- |
| GET | `/credit-rules` | 管理员或超级管理员 |
| POST | `/credit-rules` | 超级管理员 |
| PUT、DELETE | `/credit-rules/{rule_id}` | 超级管理员 |
| GET | `/credit-accounts` | 管理员或超级管理员 |
| POST | `/credit-accounts/{user_id}/adjust` | 管理员或超级管理员 |
| GET | `/credit-transactions` | 管理员或超级管理员 |
| GET | `/wechat-recharge-orders` | 管理员或超级管理员 |

鉴权依赖放在共享路由本身，不能只依赖外层入口。每次请求检查数据库中的当前角色与会话状态；普通账号返回 403、未登录返回 401。降权后的旧 Cookie 不能保留管理员能力。规则修改另外检查超级管理员角色，前端隐藏按钮不构成授权。

## 规则修改

- 点数为非负整数，不能传入布尔值或小数；金额范围与现有数据库整数列一致。名称、功能标识、计费单位和版本采用数据库字段长度限制。
- 创建时省略规则版本沿用 DAO 的默认版本；更新时省略字段保留旧值。显式 `max_cost: null` 表示解除上限，`rule_version: null` 则是无效请求，不能写入非空列。
- 最低点数不能高于最高点数。部分更新必须先锁定当前规则，再合并、校验和写入，不能在锁外读取一份可能过期的上下限。无效更新返回 422，缺失规则返回 404。
- `CreditRuleDAO.update_validated` 在同一数据库事务内完成行锁、校验和更新，返回实际修改前后的快照；服务端同步校验函数不是 HTTP 参数。传统 `update` 仍供内部调用兼容，不能把它当作已验证的管理入口。
- 删除返回实际删除的记录。重复删除保持幂等成功，但不重复记录删除成功审计。空补丁不会新增修改审计。
- 价格变更影响后续估价，不修改现有冻结记录的金额和版本。因子配置保留现有结构和计算规则，本次契约不宣称完成所有复杂计费因子的有效性审查。

## 人工调整与订单读取

人工调整先验证目标用户存在，防止为不存在的用户创建可用点数账户。增减由现有账本事务执行：锁定账户，校验余额，更新账户并写入流水，失败时回滚；冻结和赠送点数不能作为人工扣除的资金。并发扣款不能共同透支同一余额。金额必须是非零整数。

流水操作者和后台审计使用稳定用户 ID，而不是可能变化的登录名。数据库意外异常不返回原始 SQL、凭据或堆栈；失败操作不写成功审计。独立后台审计沿用现有尽力写入策略，并非与计费事务原子提交；账本内的操作者和原因才与余额变更处于同一事务。重复发送两次有效人工调整请求仍代表两次操作，本接口尚无调用方幂等键，不应自动重试不确定结果。

账户、流水、充值订单的分页大小为 1–500，偏移量非负，保留现有台账页面请求 300 条后分页的行为；现有搜索、用户、交易类型、操作者及订单状态筛选继续传给各自 DAO。充值订单列表只读取持久化状态，不主动查询支付供应商、不确认付款、不增加余额；最终支付状态由既有支付通知和查单流程维护。

## 验收边界

`test_public_admin_credits.py` 使用实际公开 HTTP 路由、密码会话、专用 PostgreSQL 和真实账本，验证角色权限、降权生效、规则 CRUD、估价、非法参数、冻结余额、流水、审计与订单筛选。并发规则用例使用独立连接和受控行锁，让两份互相冲突的补丁同时等待，验证只有一份可以成功。测试只创建并清理专用测试库内的随机规则，不接触应用或生产数据库。

该文件必须在独立公开源码树再次运行，不允许用保留私有模块或删除失败测试获得通过。完整入口仍须执行相同业务 HTTP 验收，证明抽取后没有重复路由或功能回退。隔离验收不调用支付供应商、短信或模型；不能据此宣称真实充值、浏览器交互或所有开源发行条件已验收。
