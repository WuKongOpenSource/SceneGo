# 运行时资源归属

每个应用生命周期拥有自己的数据库与 Redis 客户端。取得资源时必须立即登记清理操作：即使应用就绪前启动失败，也要释放此前取得的全部资源。前一个连接关闭报错时，仍应继续清理后续连接。

## 关闭顺序

混合入口将消费者清理与连接清理分组处理：

1. 取消并等待应用后台任务结束。
2. 要求工作进程停止，保留已有的任务优雅等待机制。
3. 取消并等待工作进程的处理任务结束，包括其拥有的心跳任务。
4. 停止并等待每个已实例化集群管理器的健康检查循环结束。
5. 关闭订阅 Redis、业务 Redis 及数据库连接池。
6. 清除进程内服务引用，不删除已持久化队列数据。

处理循环返回、抛出异常或被取消时，也必须等待心跳任务结束。调用方取消优雅停止时，不能留下继续使用即将关闭客户端的心跳。集群管理器健康循环运行期间，重复启动保持幂等；停止一个管理器不改变远程节点状态，也不启停外部节点服务。

默认超时：`BACKGROUND_TASK_SHUTDOWN_TIMEOUT_SECONDS` 为 5 秒，`WORKER_STOP_TIMEOUT_SECONDS` 为 8 秒，`WORKER_TASK_CANCEL_TIMEOUT_SECONDS` 为 5 秒，`CLUSTER_MANAGER_SHUTDOWN_TIMEOUT_SECONDS` 为 5 秒。它们限定协作式异步清理，不保证任意拒绝取消的代码、外部供应商请求、原生线程或节点作业已经终止。

## 启动与信号

ASGI 服务器拥有进程退出信号。混合运行时会临时阻止工作进程注册信号处理器；部分启动的工作进程可能在启动回滚阶段才首次被调度，因此必须等待它们结束后才能撤销保护。启动成功时，在接收请求前恢复服务器原始处理器。

混合模式和仅代理模式保留原启动行为，继续支持明确配置零个工作进程。数据库初始化失败仍阻止生产启动，现有仅开发环境回退不变。队列迁移、任务语义和点数语义不属于清理操作。

## 正式导入路径

工作进程导入不得把 `core` 目录前置到 `sys.path`，否则 Python 可能用旧名称再次加载正式模块，产生不属于应用的第二个数据库单例。内部导入使用包路径，根目录兼容模块重新导出相同对象。全新进程的导入顺序测试保护这一对象一致性，不能只依赖已经填充模块缓存的测试进程。

## 验证边界

生命周期测试注入启动、运行、取消和关闭故障，检查两种应用模式、零工作进程、重复生命周期、清理顺序、信号归属、心跳等待和正式导入。测试不得探测真实节点或消费真实生成任务。

模拟测试还须补充隔离的真实 PostgreSQL、Redis 和 HTTP 验证，包括全新进程重启及残留连接和任务检查。混合模式夹具应禁用所有节点；它验证应用生命周期，不验证 GPU 执行。修改共享在线工作进程时仍需验证公开入口。浏览器、供应商生成、注册消息送达与灾难恢复是独立验收范围。
