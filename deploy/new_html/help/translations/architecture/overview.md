# 系统架构概览

创剧将传输层、应用规则、持久化、供应商客户端与界面状态分开，使各层能够独立演进，而不向最终用户暴露供应商和部署细节。

## 后端分层

- `routers/`：校验 HTTP 请求，转换应用错误。
- `services/`：管理工作流、计费、结果挂载与编排规则。
- `dao/`：管理 SQL 及持久化相关的数据映射。
- `external_api/`：适配第三方供应商协议。
- `core/`：管理鉴权、队列、工作进程等共享基础设施。
- 根目录兼容模块：仅支持历史导入路径。

路由不得实现计费或供应商选择；供应商客户端不得修改项目状态。工作进程通过服务层回报结果，确保谱系、选用、通知及成功生成计费规则保持一致。

## 前端分层

- 页面和组件展示工作流，收集用户明确的操作意图。
- 服务模块定义接口契约，并规范化运行时能力。
- 共享工作流工具管理候选结果、选用、绑定和上游变更后的待更新状态。
- 供应商标识只用于诊断元数据，不作为对外展示名称。

## 扩展方式

增加供应商时，先扩展运行时注册表和能力清单，再映射到稳定的公开模型键。增加媒体工作流时，先定义候选结果槽位、谱系目标、选用行为、待更新依赖与计费事件，再增加界面控件。

跨媒体状态模型见[内容工作流约定](content-workflow.md)，历史导入的移除规则见[兼容性政策](compatibility.md)。
