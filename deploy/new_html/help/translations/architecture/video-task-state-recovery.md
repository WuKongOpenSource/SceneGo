# 视频任务状态恢复

工作区快照不是生成状态的权威来源。供应商任务已经完成并保存输出文件后，保存的卡片仍可能停留在进度 5%。重新加载时，必须通过已鉴权的任务接口校正快照，不得再次提交付费生成。

## 归属与恢复规则

- 通过工作区分组、视频片段，或卡片保存的精确任务 ID 匹配服务端任务；每次匹配前保留分集检查。
- 恢复已完成输出候选，但不丢弃旧候选。失败或取消的尝试应停止显示活动转圈；重试失败不能移除更早的视频。
- 一个轮询属于一张卡片和一次后端任务实例；同一实例同时最多一个状态请求。轮询停止或被替换后，忽略迟到响应和错误。
- 每个状态 GET 最长 30 秒，停止轮询时中止该 GET。临时查询失败仍使用同一任务 ID 重试；查询超时或中止 GET 都不取消或重建供应商任务。
- 支持服务端 `pending/queued` 和 `running/processing` 状态。历史终态结果停止对应轮询，并释放该次尝试的批量等待。
- 延迟的工作区恢复定时器不能重新启动已结束尝试。提示词和回调变化不能造成历史请求的渲染循环。

## 影响范围

影响两个前端版本的视频卡片、共享任务观察、工作区恢复、候选展示和批量完成等待。任务查询辅助函数只增加可选 `AbortSignal`，已有调用者保持相同 HTTP 契约。

鉴权、分集过滤、供应商载荷、原始媒体字节、数据库结构、点数结算和生成提交不变，不执行生产数据迁移。

## 回归覆盖

覆盖慢请求、卡住请求、过期的完成/失败/404 响应、同卡片重复生成、页面卸载和重新进入、所有活动任务状态、终态快照恢复、跨分集拒绝，以及真实组件从保存的 5% 卡片恢复。

组件测试同时保留旧视频和恢复的视频，并断言没有发送生成 POST。这些测试模拟供应商响应，不是新增付费生成的证据。
