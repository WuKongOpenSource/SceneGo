# 充值订单超时规则

微信充值订单自原始创建时间起满 12 小时仍未确认支付时，标记为“失败”，原因显示在充值台账中。此规则适用于待支付和二维码已过期但尚未确认支付的订单，不延长二维码本身较短的有效期。

应用在启动时及之后每分钟检查一次，不依赖浏览器持续打开。每次最多处理 500 条，跳过被锁定的订单；剩余或被锁定的订单之后继续检查。订单查询和后台台账返回前也会检查超时订单。新代码启动时，已有超时订单也包含在内。

这只是本地超时，不是退款，也不代表支付供应商已拒绝交易。后续经过身份验证和金额核验的成功通知或主动对账，仍可结算超时订单。结算保持原子性和幂等性。供应商实际拒绝或已关闭的订单不会因这一例外被重新打开。

已经支付、已有交易号或支付时间、已有点数账本记录的订单不参与超时扫描。过期查询响应和创建失败不能覆盖并发已结算订单。不会删除订单、支付记录或点数历史。

## 验证

`tests/test_wechat_recharge_expiry.py` 覆盖时间间隔、范围限定查询、启动扫描、重试和迟到对账。`tests/test_wechat_recharge_settlement.py` 覆盖超时后仅入账一次以及拒绝非法状态转换。

`tests/test_wechat_recharge_expiry_postgres.py` 进一步验证真实 PostgreSQL 行锁、临界时间与并发结算。通过 `RECHARGE_TEST_PG_PORT` 主动开启，使用仅监听回环地址的一次性测试实例、角色 `recharge_test` 和数据库 `postgres`。每个测试只创建和移除自己的随机命名 schema。绝不能把该测试指向生产环境。
