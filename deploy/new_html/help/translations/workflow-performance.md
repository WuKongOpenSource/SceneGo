# 创作流程性能约定

配音、美化和成片阶段采用有限范围渲染与按作用域读取。不会改变生成质量、源文件字节、供应商默认参数、计费、已保存时间线格式或访问控制要求。

## 性能边界

- 美化通过一次已鉴权的 `GET /api/episodes/{episode_id}/enhance-files` 请求读取当前视频和角色录音，查询前检查分集成员权限。排除已删除文件、其他分集和实体类型。已选原视频优先，即使它比当前历史页更早；否则使用最新原视频。角色录音保留每片段最多 50 条的限制，不返回文件路径、凭据和无关历史元数据。
- 音频时长按镜头一次建索引。1,000 镜头、2,000 片段夹具把片段键检查从 2,000,000 次降为 5,000 次，时长结果一致。机器相关耗时不是回归门槛，操作次数才是。
- 美化和音频时间线只渲染可见水平窗口及预留区域。播放不重建美化轨道层。指针事件按动画帧合并，保存前提交最后的指针位置。
- 成片历史每次加载 24 条，通过明确操作加载更早版本。未变的源 URL 会缓存，屏幕外视频不预加载。
- 每个应用进程最多并行生成两个未缓存缩略图。同样请求共用一个任务；缩放在异步事件循环外执行。某个查看者断开，不取消其他查看者仍需要的任务。每个请求仍单独鉴权，只缓存派生缩略图。
- 工作流数据分片共享进行中的读取。读取期间的多次修改最多排队一次后续刷新，避免修改前响应覆盖新状态。失败可重试，缓存按分集、剧本和素材作用域隔离。导航可在鼠标或焦点意图时预取代码，不预取用户数据；省流量和慢网络时不预取。

## 验证

前端回归包括 `workflowPerformance`、`sliceRequests`、`useTimelineViewport`、`EpisodeContext.loading`、音频编辑和成片分页。后端 `test_workflow_performance.py` 覆盖批量鉴权、查询语义、缩略图并发、断开、重试及事件循环隔离。

原文记录的九片段只读服务对比中，元数据请求从 18 次降到 1 次，数据库查询从 108 次降到 4 次，选中文件身份完全一致。四次运行的纯服务耗时中位数从 20.75 ms 降到 1.46 ms。这不是浏览器点击延迟，不包含网络耗时。

浏览器验收还应在慢网络下检查路由切换、长时间线滚动、播放/暂停/定位、拖动/裁剪/撤销/保存、音频覆盖、字幕、成片分页和跨分集导航。绝不能把缩略图替代送入生成的原图。
